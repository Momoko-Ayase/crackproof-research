# Crackproof 内部机制

Crackproof 是 Hypertech 开发的商用 Windows PE 文件（可执行文件与 DLL）软件保护产品。它在编译完成后施加于二进制之上：原始程序映像被加密、压缩并重新打包，随文件附带一个加载器，在文件运行时于内存中重建程序。它已在多种商业软件中发布，包括 Unity/il2cpp 游戏、原生游戏中间件 DLL 与桌面应用程序。

本文档是一份关于 **Crackproof 内部工作机制** 的研究报告，来源于对受保护二进制及其所携带加载器代码的静态与动态分析。内容涵盖：

- **受保护文件在磁盘上的形态**——容器布局、加密头部，以及如何识别与分类受保护文件。
- **数据变换**——密码族、校验和链、压缩格式，以及每个受保护文件都携带的按构建定制字节变换。
- **分阶段加载器**——自举代码本身如何被拆分为逐级解密的加密阶段，以及原始程序节如何被恢复。
- **加壳器对 PE 的改造**——哪些头部字段、表与目录被移除、加密或搬迁，以及加载器在运行时重建了什么。
- **受保护二进制运行时做了什么**——环境与反分析检查、内核驱动、手动映射子模块，以及按需页解密。
- **已观察到的弱点**——出于研究目的记录的、特定检查或机制失效之处。

## 本文档不是什么

本文档不是任何工具的使用指南，也不包含针对任何具体产品绕过保护的指引。所有结构与算法均在格式层面描述，并在有助于精确定义处给出 Python 参考实现。构建家族一律以通称指代（如“较旧的 64 位 EXE 构建”“无标记布局”）；不出现任何具体受保护产品的名称。

## 约定

- 除非另有说明，所有偏移均为自文件起始的十六进制字节偏移。`u32@X` 表示偏移 X 处的小端 32 位值。
- **RVA**（相对虚拟地址）按 PE 的通常含义使用。加载器在按 RVA 布局的内存映像上工作；在磁盘上，同一偏移也被用作解包后映像缓冲区内的文件偏移。
- 整数运算为固定宽度（32 位或 8 位）回绕运算，与算法来源的 x86 环境一致。Python 参考代码中显式施加掩码。
- 诸如 `info[3]` 的名称指从加密文件头派生的 8-dword 表中的条目（见[受保护文件格式](file-format.md)）。
