# PE 变换

节内容加密只是加壳器工作的一半。PE 结构本身也被拆解：Windows 加载器需要的字段被移除或加密，由运行时加载器在解包后重新创建。本页编目每项变换及其运行时对应物。它面向两类读者：静态分析受保护文件的人（结构不在 PE 工具期待的位置），以及验证重建映像的人（每项变换都有一个必须已发生的还原步骤）。

## 节表变成内存布局

普通 PE 通过节表把文件偏移映射到 RVA。受保护映像存储的则是加载器在内存中产出的布局：每节的 `SizeOfRawData` 设为其 `VirtualSize`，`PointerToRawData` 设为其 `VirtualAddress`。节内容于是统一按 RVA 寻址，磁盘与内存一致。

32 位家族在最后一步加上逆变换：把 RVA 布局的映像压实回文件对齐的 PE——头部位于 `0x400`，各节按 `0x200` 文件对齐连续排布，裁掉每节原始数据尾部的零串，并重写 `FileAlignment`/`SizeOfHeaders`。

## 入口点与数据目录被加密

`AddressOfEntryPoint` 与全部十六个 `IMAGE_DATA_DIRECTORY` 项加密存放在映像基址（`info[3]`）附近，以位置密钥字节密码包裹。每种位宽有两种摆放：

| 家族                    | 块起始              | 入口点     | 数据目录    | 加密长度     |
| --------------------- | ---------------- | ------- | ------- | -------- |
| 64 位 “Layout A”（标记布局） | `info[3] + 0x40` | `+0x40` | `+0x50` | 144 字节   |
| 64 位 “Layout B”（无标记）  | `info[3] + 0x20` | `+0x20` | `+0x30` | 144 字节   |
| 32 位 “Layout A”       | `info[3] + 0x40` | `+0x40` | `+0x50` | 144 字节   |
| 32 位 “Layout B”       | `info[3] + 0x10` | `+0x20` | `+0x30` | 0x290 字节 |

64 位标记构建上摆放靠探测：试解候选入口点之后的 dword，检查是否等于映像基址。32 位上选择器是 `info[3] + 0x10` 处的 dword（大于 `0x10000` → Layout B）。该块被**临时**解密——入口点写入 `pe + 40`，128 字节目录写入 `pe + 136`（64 位）或 `pe + 0x78`（32 位）——随后加密字节被复原：受保护文件即使在其他一切解包完成后仍保持该区域加密，因此正确的重建结果在 `info[3] + ep_off` 处依然显示密文。

运行时加载器不直接使用的 PE 头字段在磁盘头部保持抹除状态，直到这次还原运行——这就是为什么 PE 工具在受保护文件上显示垃圾入口点（常见的小值如 `0x1B5C`）。

## 导入：加密的名字，重建的表

导入名（DLL 名与按名函数名）以字符串密码加密，密钥是各字符串自身 RVA 的低字节。各家族的还原遍历不同，但收尾规则一致：

* 每个名字就地解密并转小写。
* 按名 thunk 的 hint/name 字符串被解密，2 字节 hint 字段清零。序数 thunk（最高位置位——PE32+ 为 bit 63，PE32 为 bit 31）跳过。只读 PE32+ thunk 的低 dword 会把序数误当成小 RVA 而破坏头部——8 字节宽度很关键。
* IAT 数据目录（第 12 项）边界经由首个 thunk 追踪恢复。

表来源各异：

* **标记布局（64 位）**：stage 5 内的 walk5 加密指针表。
* **无标记布局**：PE 导入目录本身，由 `DataDirectory[1]` 驱动——当元数据的导入目录为零时（托管 DLL 常见）回退到锚点阶段保存的值。名字解密在代码页扰动之后运行，因为这些构建上导入字符串位于 `.text` 内。
* **专用 DLL 布局**：现有表的就地解密。
* **32 位**：EighthStage 导入表，或校验更优时取元数据目录。

**`.kmiat` 搬迁（32 位 EXE）。** 当加载器写出的 IAT 与原 `.idata` 布局不符时，导入元数据（描述符、查找表、名字池）被重建进最后一节，更名 `.kmiat`，大小 `0x7000`，特征 `0xE0000060`；活动 IAT 留在原 RVA，导入目录改指新表。`api-ms-win-crt-*` 名归一为 `ucrtbase.dll`。DLL 跳过此步——它们保留真实的导入表。

## TLS 被剥离并在运行时重装

加壳器移除整个 `IMAGE_TLS_DIRECTORY`：数据目录项、结构体、原始数据模板，以及覆盖结构体指针字段的基址重定位。运行时加载器在映射模块时自行重装 TLS。

静态重建的映像得不到这种待遇——普通 Windows 加载器需要有效的 TLS 目录，否则不会分配 TLS 槽、不会写 `_tls_index`。此后每次 C++ `thread_local` 访问都经由一个垃圾槽解析，模块在初始化期间崩溃（运行时初始化深处 `0xC0000005`）。真正的目录在加载器 stub 的 `.rdata`/`.tls` 中以明文幸存（单文件构建保留在受保护文件内；伴生布局保留在 stub 中），因此重建时按 RVA 逐字节覆盖结构体与原始数据模板，并为结构体的四个 64 位指针字段追加 `DIR64` 基址重定位。较旧的单文件构建早于这种剥离，根本没有 TLS 目录。

## 导出以明文幸存——在别处

导出目录在 payload 中从不加密。它住在哪里取决于布局：

* **单文件布局**：导出区域以明文留在受保护文件中其 RVA 处；加载器原样拷入映像。（该区域经 `DataDirectory[0]` 定位，可从明文头部读取。）
* **外置伴生布局**：伴生体在导出区域解密为垃圾（`NumberOfFunctions` 等均为密文）。运行时加载器从 stub `.rdata` 中保留的明文副本重建导出。静态重建同样必须从 stub 覆盖导出目录区域，否则分析工具会在导出表上出错。

## 重定位与 /FIXED 分野

各构建刻意在结果可否重定向上不同：

* **较旧单文件 EXE 构建是 `/FIXED`。** 外壳丢弃基址重定位表并清空 `DllCharacteristics`；映像只能在首选基址加载。忠实的重建镜像这一点：`DataDirectory[5]` 清零、`DllCharacteristics` 清零。
* **DLL（任何布局）必须保持可重定位。** DLL 几乎总是被映射到非首选基址；剥离其重定位会使其无法加载。重建保留 `DataDirectory[5]` 并确保置位 `IMAGE_DLLCHARACTERISTICS_DYNAMIC_BASE`（`0x0040`）。
* **无标记与伴生构建不是 `/FIXED`。** 它们携带真实的 ASLR 标志与有效重定位表，任何重定向都必须重定位一切——包括已还原 TLS 目录的指针，这正是 TLS 还原期间要追加重定位的原因。

## 代码页扰动，排在最后

页级扰动在节恢复之后施加于 `.text`。各家族观察到的顺序约束：

* **标记布局**：扰动在入口点/数据目录还原之前运行。
* **无标记布局**：扰动推迟到导入名解密之后，并在最终字节上重新选择——且仅当入口点落在 `.text` 内才运行。托管 DLL 在扰&#x52A8;_&#x4E4B;&#x540E;_&#x624D;恢复 CLR 元数据，因为元数据区域位于 `.text` 内但不是被扰动的代码：扰动它会每 16 字节约破坏 1 字节，产生无效的 COR20 签名。
* **32 位**：当节已是明文（原生 DLL）时完全跳过扰动，通过比较 `0xCC` 还原得分与无扰动基线来检测。

## 托管（.NET）结构被保留而非加密

对托管 DLL，COR20 头（`cb == 0x48`）与 BSJB 元数据流在受保护文件中按其 RVA**原样**幸存——只有周围代码被加密。还原时（经受保护文件节表映射后）把二者从原文件逐字节拷回，在代码页扰动之后进行。反之，当构建抹掉了 CLR 头（`cb` 为零的 COR20），数据目录项被清除，使映像按原生加载，而不是交给会在空头上崩溃的 `mscoree!_CorExeMain`。

Unity il2cpp 作品在 PE 之外还有第二层独立混淆：`global-metadata.dat` 内的方法令牌。见 il2cpp 元数据混淆。

## 清零列表

并非原始映像的每个区域都被存储：`.bss` 类区域以清零列表交付——64 位的 walk4 第二条链、32 位的 zero-list 簇槽位，以及专用 DLL 布局的收尾清零链。每项是一个 `(dst, size)` 对，以与节描述符相同的 16 字节位置链解密，在解压之后（32 位：之前）清零。

## 关于节特征的一点说明

一个微妙的非变换：只读的 `.rdata` 特征必须原样保留。把 `.rdata` 标为可写会破坏静态链接的 MSVC/UCRT 映像——CRT 的浮点格式初始化（`_cfltcvt_init`）被一道安全检查门控，该检查拒绝位于可写节的初始化描述符；跳过它会留下 `R6002 - floating point support not loaded` 桩，在首个 `%f` 格式调用时中止。Windows 加载器在捕捉导入时本就会临时把 IAT 页置为可写，因此原始的只读特征已足够。
