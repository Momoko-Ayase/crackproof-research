# 支持範圍

目標是 Windows 10/11。當前執行證據是 Windows 11 內部版本 26100，使用源碼構建的 x86/WOW64 與 x64 程序。尚未單獨在 Windows 10 上運行。

可選內核提供程序有獨立的構建與驗證邊界。它是實驗性的，沒有 `protect` 選項，也不構成商用驅動兼容或已驗證內核強制的聲明。

| 輸入 | 內嵌族 | 伴生族 |
| --- | --- | --- |
| 原生 x86 EXE/DLL | PE32 | PE32 |
| 原生 x64 EXE/DLL | 經典/現代 PE32+ | 經典/現代 PE32+ |
| 原生 x64 DLL | 遺留 DLL | 不適用 |
| 僅 IL 的 x86/AnyCPU DLL | PE32 | PE32 |
| 已識別的僅 IL x86/AnyCPU C# EXE | PE32 | PE32 |
| 僅 IL 的 x64 DLL | 遺留/經典/現代 PE32+ | 經典/現代 PE32+ |
| 僅 IL 的 x64 EXE | 經典/現代 PE32+ | 經典/現代 PE32+ |
| 清除 `ILONLY` 的純 IL x86/AnyCPU/x64 DLL | 與同架構僅 IL 行相同 | 與同架構僅 IL 行相同 |

原生 IL2CPP PE 使用原生行。獨立的 `global-metadata.dat` 混淆不在本實現範圍內。

託管執行覆蓋適用主機上的 Framework 4.8 x86/x64、CoreCLR 10.0.12 x64 與 Mono 6.13 x86。純 IL、僅清除 COR20 `ILONLY` 位的程序集在滿足下列限制時會被接受。

## 明確拒絕

- 需要靠節名或權限規範化才能讓 Senbei 可執行導入恢復成功的原生 PE32 EXE。
- 帶代碼導出且啟用 `IMAGE_GUARD_XFG_ENABLED` 的原生輸入。
- 故意放在可執行節中的導出數據。
- 未使用的 RVA 頁 `[0x1000,0x2000)` 已被佔用的現代託管零導入佈局。
- 頁加密實際開啟時含可寫可執行節的輸入。

託管打包還會拒絕：

- 真正的 C++/CLI 混合模式、原生 CLR 入口點或修補記錄、ReadyToRun/AOT，以及非 IL 方法實現。
- 帶強名稱或延遲簽名的程序集、多模塊程序集，以及鏈接或導出的模塊內容。
- 原生導出、原生異常/啟動表、TLS、加載配置表或延遲導入。
- `VirtualSize` 大於 `SizeOfRawData` 的節、已有指針或 Edit-and-Continue 元數據表，以及實現了 CLI vararg 的方法。
- 位於保留命名空間 `Arare.Managed` 中的輸入類型。

這些是輸入限制，不是上述 CLR 主機之間的差異。關閉環境檢查不會讓不受支持的程序集佈局變得可用。

託管準備還會把用於泛型填充而新增的 TypeDef 限制在 524,288 個以內。簽名解析允許 128 層類型，每個解析的返回類型最多包含 65,536 個類型元素。超過這些工作量限制的輸入會被拒絕；這些限制不是進程內存的硬性預算。

配置描述的是已觀察的結構族，不是商用雲版本。剩餘的商用保真缺口包括主機目錄准入、未識別的 E 系列對象、已加載模塊完整性節奏、已驗證的商用默認矩陣，以及 Windows 10 執行。
