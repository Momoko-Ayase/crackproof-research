# 対応範囲

Arare は Windows 10 および Windows 11 をターゲットとしており、ソースビルドした x86/WOW64 および x64 のネイティブ／マネージドプログラムを用いて Windows 11 ビルド 26100 上で実行検証を行っています（Windows 10 実機での通しテストは未実施です）。マネージド実行は .NET Framework 4.8（x86/x64）、CoreCLR 10.0.12（x64）、および Mono 6.13（x86）で確認済みです。

## 対応入力マトリクス

| 入力種別 | 埋め込みプロファイル | コンパニオン（`._`）プロファイル |
| --- | --- | --- |
| ネイティブ x86 EXE または DLL | `pe32` | `pe32` |
| ネイティブ x64 EXE または DLL | `pe64-classic`, `pe64-modern` | `pe64-classic`（DLL は非ゼロのエントリポイントが必須）, `pe64-modern` |
| ネイティブ x64 DLL（専用レイアウト） | `legacy-dll` | 非対応 |
| IL のみの x86 または AnyCPU DLL | `pe32` | `pe32` |
| 認識対象の IL のみ x86 または AnyCPU C# EXE | `pe32` | `pe32` |
| IL のみの x64 DLL | `legacy-dll`, `pe64-classic`, `pe64-modern` | `pe64-classic`, `pe64-modern` |
| IL のみの x64 EXE | `pe64-classic`, `pe64-modern` | `pe64-classic`, `pe64-modern` |
| `COR20` の `ILONLY` がクリアされた純粋 IL DLL | 該当ビット幅の IL のみ DLL と同じ | 該当ビット幅の IL のみ DLL と同じ |

ネイティブの IL2CPP バイナリ（`GameAssembly.dll` およびホスト EXE）は通常のネイティブ PE として保護できます。単体の `global-metadata.dat` 難読化は Arare の対象外です。

## パック時の拒否条件

`arare protect` は次のいずれかに該当する入力を拒否します。

### ネイティブおよび共通 PE の制約

* **エントリポイントがゼロの classic コンパニオン DLL:** `AddressOfEntryPoint` がゼロの `pe64-classic` コンパニオン DLL（エントリポイントを持たない DLL には埋め込み格納または `pe64-modern` を使用してください）。
* **コンパニオン TLS の重複:** TLS エントリ範囲がローダーの保持する物理データ領域と重なる x64 コンパニオン入力。
* **ページ暗号化時のアライメントと権限:** ページ暗号化が有効な場合の、書き込み・実行両方が可能な（`RWX`）セクション、`SectionAlignment < 0x1000`、または `VirtualAddress` が `0x1000` 境界に揃っていない実行可能セクション。
* **バウンドインポートのみの記述子:** `OriginalFirstThunk == 0` であり、イメージ内に hint/name の RVA または VA を持たないネイティブインポート記述子。
* **PE32 EXE のインポート正規化制約:** 静的アンパッカーによるインポート復元のためにセクション名やセクション権限の書き換えが必要となるネイティブ PE32 EXE。
* **XFG コードエクスポート:** コードエクスポートと `IMAGE_GUARD_XFG_ENABLED` を併用しているネイティブモジュール。
* **イメージおよびヘッダーの上限:** 追加される Arare セクションを含めた総イメージサイズが `1 GiB` 超、セクション数が `96` 超、またはセクションヘッダー領域が `0x1000` バイト（`pe64-*` / `legacy-dll`）もしくは `0x400` バイト（`pe32`）を超える入力。

### マネージドアセンブリの制約

* ネイティブコードを含む本来の C++/CLI 混合モードアセンブリ、ネイティブ CLR エントリポイントや vtable fixup、ReadyToRun / AOT イメージ、または非 IL メソッド本体を含む入力。
* 厳密名署名（strong-name）または遅延署名されたアセンブリ、マルチモジュールアセンブリ、リンク／エクスポートされたモジュールテーブル、埋め込み Portable PDB、または番号 `>= 45` の CLI メタデータテーブル（`/debug:embedded` など）。
* `ILONLY` がクリアされた x86 マネージド EXE、`32BITREQUIRED` または `32BITPREFERRED` が設定された PE32+ マネージド入力、RVA ページ `[0x1000, 0x2000)` が使用済みのインポートなし `pe64-modern` アセンブリ、またはインポートディレクトリが非ゼロでありながら先頭記述子が空の `pe64-modern` マネージド入力。
* ネイティブエクスポート、ネイティブ例外／アンワインドディレクトリまたは TLS ディレクトリ、Load Config テーブル、遅延読み込みインポート、`VirtualSize > SizeOfRawData` のセクション、Edit and Continue／ポインター系メタデータテーブル、CLI `vararg` メソッド、または予約済み名前空間 `Arare.Managed` 内の型を含む入力。
* ジェネリックパディング用 `TypeDef` 行の追加数が `524,288` を超えるメタデータ拡張、またはシグネチャの戻り値型におけるネスト深さ `128` 超もしくは型要素数 `65,536` 超。

## レイアウトと実行時ロードに関する注意

* **実行可能セクション内のデータエクスポート:** PE のエクスポートテーブルにはコードとデータの区別がないため、実行可能セクション内を指す非フォワーダーエクスポートはパック時に拒否されず、コードエクスポート保護用のガードサンクでラップされます。エクスポートするデータシンボルは非実行データセクションに配置してください。
* **バイト配列ロードとディスクロード:** コンパニオン形式で保護されたマネージドアセンブリはディスク上のファイルを必要とし、`Assembly.Load(byte[])` によるロードは拒否されます。`ILONLY` がクリアされた純粋 IL DLL は標準の CLR 混合モードロード規則に従います（.NET Framework および CoreCLR では同一ビット幅のプロセスでディスクからロードする必要があり、Mono ではディスクとバイト配列の両方からロード可能です）。
