# Htsysm カーネルコンポーネント

CrackProof でオプションとして導入されるカーネル層（`Htsysm`）は、これまでに 3 世代のドライバアーキテクチャへと変遷しています。

{% tabs %}
{% tab title="第 1 世代: HtsysmNT" %}
### 呼び出し元検証なしのカーネルシェルコード実行

第 1 世代は、呼び出し元が渡した Ring-0 シェルコードを認証なしでそのまま実行する IOCTL を公開しています。ユーザーモード側の補助モジュール `cm` はこのプリミティブを利用して 2 つのカーネルモード DLL（ステータス `B21` で `HtsyskNT.dll`、ステータス `BB0` で `HtpecmNT.dll`）をカーネル空間へ手動マップし、それぞれの `_FarEntry@0` エクスポートを呼び出してカーネルメモリアクセスやプロセスの強制終了を行います。ローカルの任意のユーザーモードプロセスが同じ IOCTL を発行できるため、このドライバが導入された環境ではマシン全体に任意の Ring-0 コード実行を許すことになります。
{% endtab %}

{% tab title="第 2 世代: Htsysm7679" %}
### 範囲制限付き `EPROCESS` マスク DWORD 編集（`0xAA01`）

第 2 世代（`Htsysm7679`、デバイスタイプ `0xAA01`、IOCTL `0xAA013880` / `0xAA013884` / `0xAA013888`）では汎用シェルコード実行が廃止され、代わりに符号なしオフセット `offset < 0x1000` の範囲内で `IoGetCurrentProcess() + offset` に対する 32 ビットのマスク付きビットクリア・ビットセット・読み取りを行います。

* **保護プロセス（`PP`）の切り替え:** ステージ `C03`/`C04` において、ローダーは自プロセスの `EPROCESS` 内にある保護プロセス（Protected Process）ビットフィールドをセットし、ユーザーモードのデバッガやインジェクタがフルアクセス権限のハンドルを開けないようにします。ただし `PP` 状態のままでは一部の Win32/NT API（`NtCreateSection` など）が失敗するため、ユーザーモードローダーは対象 API にフックを仕掛け（`C04` で記録）、呼び出しのたびに一時的に `PP` を解除して元の API を実行し、直後に `PP` を再設定します。
* **BYOVD としての悪用リスク:** 呼び出し元の検証が可逆な PID 単位の簡易暗号のみに依存しているため、同じ PID 変換を再現した任意のローカルプロセスが自プロセスの `EPROCESS` フィールド（`offset < 0x1000`）を書き換えたり、`C04` で `PP` が有効化される前のターゲットへインジェクションしたりすることが可能です。
{% endtab %}

{% tab title="第 3 世代: Htsysm767901・Htsysm1B4001" %}
### `ObRegisterCallbacks` によるハンドル権限ストリップ（`0xAA02`）

第 3 世代（`Htsysm767901` および `Htsysm1B4001`、デバイスタイプ `0xAA02`、`0xAA023800..0xAA02382C` の 12 個の IOCTL）では `EPROCESS` の直接書き換えが完全に廃止され、代わりにオブジェクトマネージャのコールバック（`ObRegisterCallbacks`、`Htsysm1B4001` での `Altitude` は `1B4001` に由来する `88180.011104000001`）を登録して、最大 100 個の保護対象プロセスと 12 エントリのテレメトリリングを管理します。

* **ストリップされるアクセスマスク（`& 0xFFFFFFC5`、`0x3A` をクリア）:** 許可されていないプロセスからのハンドルオープンおよび複製に対し、`PROCESS_CREATE_THREAD`（`0x02`）、`PROCESS_VM_OPERATION`（`0x08`）、`PROCESS_VM_READ`（`0x10`）、`PROCESS_VM_WRITE`（`0x20`）の権限を剥奪します。
* **除外ルール:** `KernelHandle`、自己アクセス、設定された最大 5 個の呼び出し元 PID（`0xAA02380C`）、最大 3 個の呼び出し元親 PID（`0xAA023810`）を許可するほか、**設定されたシステムディレクトリ配下から実行されている場合に限り** `csrss.exe`、`lsass.exe`、`conhost.exe`、`svchost.exe` を許可します（システムディレクトリは `0xAA023800`、`svchost.exe` の想定親 PID は `0xAA023814` で指定）。
* **3 ステートのハンドシェイク:** 保護対象への登録には静的な PID 暗号ではなく自己コード領域とリターンアドレスのハッシュ検証が用いられ、ユーザーモード呼び出し元にカーネルメモリ書き込みプリミティブを一切与えません。
{% endtab %}
{% endtabs %}

## バージョンスタンプ（`0x7679` と `1B40`）

`Htsysm7679` / `Htsysm767901` の名前に含まれる `0x00007679` は、PE32 の `EighthStage` や Stage 5 マーカーテーブルに現れる構成クラスタのスタンプ `0x00007679` と一致します（[PE32・DLL・マーカーなしレイアウト](../loading-and-pe-repair/loading/layout-variants.md)を参照）。ステージ `C02`/`C03` で `Htsysm1B4001` を記録する新しい Windows ビルドは、Android ビルドと共通の `1B40` スタンプを持ち、第 3 世代の `0xAA02` コールバックドライバを使用します（そのため `C04` で必要となるユーザーモード API フックが減っています）。また、これらのビルドでは `E` 系のデバイス検査（`E55`、`E91`）が頻繁に有効化されます。
