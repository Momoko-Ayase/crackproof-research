# 起動シーケンスとステータス通知

本来のプログラムコードが実行される前に、CrackProof はホストスタブと手動マップされた補助モジュール群にまたがる起動パイプラインをビルド設定に従って実行し、最終ステータス `280`（OEP へのジャンプ）に到達します。

```mermaid
flowchart LR
    S200["200..210\n初期化・アーキ確認"] --> P1["410..540\nPhase 1 検査"] --> KRN["C00..C04 / Bxx\nOS・Htsysm"]
    KRN --> ASEQ["Axx シーケンサ\n・DLL A15"] --> PRE["5D0..5E2, 5C0\n復号前処理・DLL"]
    PRE --> DEC["610, [640], 655, 6E1\n一括復号・再配置"] --> PG["800..840, 660\nまたは 800, 830"]
    PG --> EX["[E20..E91]\nドライバ検査"] --> OEP["280\nOEP へジャンプ"]
```

## 起動シーケンスとステータスコード <a href="#the-boot-sequence-and-status-codes" id="the-boot-sequence-and-status-codes"></a>

有効化された各ステージは、12 ビットの 16 進ステータスコードを記録します。

| コード | ステージ内容 |
| --- | --- |
| `200` / `210` | ローダー起動 / ホストアーキテクチャ確認 |
| `410` | ユーザーモード耐デバッグ検査（`IsDebuggerPresent`。実機キャプチャ上、商用 `410` 内に SEH サブステージは存在しません） |
| `510` | ローダーのメモリ範囲に対する CRC-32 整合性チェック |
| `520` / `52F` | `NtQueryInformationProcess` によるデバッグ検査 / カーネルデバッガ検査 |
| `540` | VMware I/O ポートバックドアプローブおよび CPU 機能フラグ確認 |
| `560` / `561` | セクション復号セットアップ / 補助モジュールの選択 |
| `C00` | Windows 最小ビルド番号チェック。ホストのビルド番号と最小要件ビルド番号をそれぞれ `(0x01A00000 + build)` の 2 つの DWORD として記録 |
| `C01` | ブート構成チェック（`testsigning`、`disableintegritychecks`） |
| `C02` / `C03` / `C04` | `Htsysm` サービス（`Htsysm7679`、`Htsysm767901`、または `Htsysm1B4001`）の登録 / ドライバ初期化 / コールバック登録または `EPROCESS` 保護プロセス化と API フック適用 |
| `A03` | 親プロセス確認（`explorer.exe` / `cmd.exe`） |
| `A09` | VM ハードウェア／BIOS レジストリ値のプレフィックス検査 |
| `A0F` | 注入 DLL スキャン |
| `A08` / `A04` | ディスク上の正規 `ntdll` / `kernel32` からクリーンな `.text` をコピー（`A04` はディスク上のシステム DLL 自体が改変されている場合も中断） |
| `A07` / `A01` | 想定外の外部スレッドを強制終了 / 外部スレッドが残存している場合に中断 |
| `A11` | DLL ホストプロセス検証（ホスト EXE 内の `peC` セクション、または大文字・小文字一致の `KeRnEl32.dLl` インポートを確認） |
| `A15` | ホスト検証通過後、`5D0` の直後に記録される DLL シーケンサマーカー（検査処理本体はなく、EXE では記録されません） |
| `B00` / `BD0` / `BE0` | 互換 OS チェック / `C:\Windows\msc.log.log` 不在確認 / 旧 SoftICE・Syser デバイス確認 |
| `B21` / `BB0` | 旧世代ドライバ補助モジュールのロード（`HtsyskNT.dll` / `HtpecmNT.dll`） |
| `5D0` `552` `570` `590` `5B0` `5B1` `598` `5A0` `5E1` `5E2` | 段階的な復号前処理ステップ |
| `A06` / `5C0` | 後段の API フック設定 / インポート先ランタイム DLL のロード |
| `610` | セクションおよびヘッダの一括復号 |
| `640` | ページ保護適用前の実行ページ一括復号 |
| `655` / `6E1` | ベース再配置（Base Relocation）の適用 / 末尾セクションのセットアップ |
| `800` `810` `820` `840` | ページ保護のセットアップ（`800`..`820`）、`KiUserExceptionDispatcher` フック設置およびページの再暗号化と `PAGE_NOACCESS` 設定（`840`） |
| `830` | ページ暗号化を行わないネイティブビルドでのページ設定完了（`800` -> `830`） |
| `660` | ページ保護設定後、`280` へ移行する前のハンドオフ処理 |
| `E20` `E40` `E52`..`E59` `E55` `E91` | `1B40` 系ビルドにおける後段の整合性チェックおよび解析系ドライバデバイス検査 |
| `280` | 本来のエントリポイント（OEP）への最終ハンドオフ |

複数モジュールを含むプロセスのキャプチャでは、モジュール単位の設定差を確認できます（[サンプルデバッグログ](https://app.gitbook.com/s/XSPACE_REFERENCE_JA/sample-debug-logs)を参照）。ページ暗号化が有効なホスト EXE は `610 -> 640 -> 655 -> 6E1 -> 800..840 -> 660 -> 280` の順に遷移する一方、同一プロセス内で一括復号されるネイティブプラグイン DLL は `610 -> 655 -> 6E1 -> 800 -> 830 -> 280` の順で遷移します。`A` 系の各チェックは、単一のモード駆動型シーケンサが複数のパスに分けてディスパッチします。

## デバッグログ <a href="#debug-logging" id="debug-logging"></a>

* **`%temp%\<12 hex>` フォルダゲート:** 保護された各モジュールは 16 進 12 桁のフォルダ名を導出します。`%temp%\<12 hex>` が存在し、かつその作成日時がおおむね 48 時間以内であれば、ローダーは平文のトレースファイル（EXE は `HHMMSSmmmE-...`、DLL は `HHMMSSmmmD-...`）を書き出します。`CreateFileW` にフックまたはブレークポイントを仕掛ければ、探索先のパスを即座に特定できます。
* **`\\.\mailslot\ErrLog-Pec<4 hex>` チャネル:** 独立した診断用メールスロットチャネルで、16 進 12 桁ログ鍵の先頭 16 ビットワード `key` から `((key + 1) * 0x3039) mod 0x8003` によって `<4 hex>` を導出します。メールスロットのリスナーが存在する場合、`-- Version` 以降のデータをローリング XOR（`state = (derive(key) + 1)^2 ^ ~length; word ^= state; state = ror32(state + i, 7)`）で難読化したレポートを送出します。
* **`AAA-BBB-CCC` 終了コード:** 両チャネルとも、末尾に 9 文字のステータスコードを出力して閉じます。
  * **`AAA`（10 進 3 桁）:** 正常起動時は `000`、失敗時は全 104 エントリのステージテーブルにおける失敗ステージの 1 始まり 10 進インデックス（例：`C03` -> `046`、`A09` -> `048`、`E91` -> `601`）。
  * **`BBB`（大文字 16 進 3 桁）:** 失敗ステージの実行中に最初に記録されたサブステージコード。
  * **`CCC`（大文字 16 進 3 桁）:** `BBB` が未設定の間に最初に記録された原因／エラーコード（観測例：`046-019-01F`、`048-012-002`、`601-000-008`）。

{% hint style="info" %}
**メモリ上でのステータスコード出力箇所の特定:** ログ出力ヘルパーは `ECX` に 12 ビットのコードをパックして受け取ります。下位ニブルのタグは、ステージステータスが `1`（`(code << 4) | 1`、例：`0xC01` -> `0xC011`）、`CCC` 原因コードが `3`（`(code << 4) | 3`）、`BBB` サブステージコードが `5`（`(code << 4) | 5`）です。ホストモジュール自身のローダーセクション内に置かれているのは中核ブートストラップの即値（`200`、`560`、`590`、`5A0`、`5E1`、`5E2`、`800`）のみで（Phase 1 の即値は実行後にゼロ消去されます）、`410`/`510`/`520`/`540`、`Cxx`、`Axx` の即値は手動マップされた補助 DLL（`HtpecIt`、`dm` など）の内部にあります。
{% endhint %}
