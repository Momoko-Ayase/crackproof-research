# 確認されている設計上の制約

複数の Windows ビルド系統に対する静的解析と実機検証を通じ、再現性のあるアーキテクチャ上の制約が 8 点確認されています。

* **前方一致のみの VM レジストリ判定（`A09`・`540`）:** `A09` は BIOS／システム系の 3 つのレジストリ値に対してベンダ文字列を前方一致でのみ照合するため、`SystemBiosVersion` の末尾側にハイパーバイザ識別子が入る環境や `SMBIOS.reflectHost = "TRUE"` を設定した環境を検知できません。また、`540` のバックドアプローブは `monitor_control.restrict_backdoor = "TRUE"` で無効化されます。
* **平文の `%temp%` トレース出力機構:** `%temp%` 配下に 16 進 12 桁のフォルダを作成するだけで、商用ローダー自身がステージ番号、モジュールベースアドレス、未解決インポート、フック対象 API、`AAA-BBB-CCC` の失敗箇所をすべて平文で書き出します。
* **プロセス内でのオンデマンドページ復号:** `HtdpStub2.dll` が設置する `KiUserExceptionDispatcher` フックは、同一プロセス内のどのスレッドで発生したアクセス違反（`STATUS_ACCESS_VIOLATION`）であっても該当ページを復号します。そのため、保護対象ページへ順次アクセスして復号を発火させ（必要に応じて `scribble` のマスクも解除すれば）、実行可能セクション全体を復元できます。
* **旧世代カーネルドライバの攻撃対象領域:** 第 1 世代（`HtsysmNT`）は認証なしの Ring-0 シェルコード実行を公開しており、第 2 世代（`Htsysm7679`）は `offset < 0x1000` の `EPROCESS` マスク書き込み IOCTL を可逆な PID 暗号のみで保護しています（署名済みビルドは BYOVD プリミティブとして悪用可能です）。ユーザーモード呼び出し元に権限昇格プリミティブを与えない設計になっているのは第 3 世代（`0xAA02` の `ObRegisterCallbacks`）のみです。
* **外部鍵を持たない自己完結型チェックサム連鎖:** 鍵スケジュール、ハフマンテーブル、バイトコードスタブはすべてコンテナ内に同梱されており、各ステージの鍵も外部の非対称鍵を使わず標準 CRC-32 と決定論的な算術演算のみで導出されます。そのため、ペイロードを書き換えた場合でも後続ステージの鍵を再計算できます。
* **偽装可能な `A03`・`A11` プロセス判定マーカー:** `A03` は親プロセスの実行ファイル名（`explorer.exe` / `cmd.exe`）を確認するのみで、`A11` も暗号学的なホスト認証ではなく `peC` セクション名または大文字・小文字一致の `KeRnEl32.dLl` インポート文字列によって CrackProof ホスト EXE を識別します。
* **短いメモリ上ホストスタンプ検査:** ロード後のホストイメージ内にある追加のバイトマーカーを確認するビルドでも、ホストコード全体のハッシュ検証ではなく固定の数バイトのみを検査しています。
* **限定的なユーザーモード耐デバッグ範囲:** 実機キャプチャ上、商用の `410`/`520` は `IsDebuggerPresent` と `NtQueryInformationProcess` に依存しており（`410` 内部に SEH 耐デバッグサブステージはありません）、`A0F` も既知の代表的なインジェクション DLL 名の固定リストを走査するにとどまります。
