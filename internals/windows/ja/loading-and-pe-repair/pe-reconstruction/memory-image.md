# ヘッダー・セクション・ゼロ充填範囲

CrackProof はセクション本体の暗号化に加え、PE ヘッダーの各フィールド（`AddressOfEntryPoint`、一部の `IMAGE_DATA_DIRECTORY` エントリ、およびセクションの Raw データフィールド）をクリアまたは差し替え、起動時にメモリ上で復元します。

## RVA 配置のセクションヘッダーと 32 ビットのディスク配置への詰め直し

64 ビットの出力（および 32 ビットの作業バッファー復元中）では、ファイルオフセットと RVA が一致するようセクションヘッダーをメモリ配置に正規化します。

* `SizeOfRawData = VirtualSize`
* `PointerToRawData = VirtualAddress`

32 ビット（`PE32`）の出力では、最終パスでこの RVA バッファーをディスクアライメントに沿ったコンパクトな PE へ詰め直します。ヘッダー末尾は `0x400` となり、各セクションは末尾のゼロパディングを `SizeOfRawData` から切り詰めたうえで `0x200`（`FileAlignment`）境界に順次配置され、あわせて `SizeOfHeaders` と `FileAlignment` が更新されます。

## 一時復号されるエントリポイントおよびデータディレクトリブロック

`AddressOfEntryPoint` と 16 個の `IMAGE_DATA_DIRECTORY` エントリ（計 128 バイト）は、`byte_rotate2` で暗号化された状態で `info[3]` 付近に格納されています。

| 系統・バリアント | ブロック開始位置 | エントリポイント位置 | ディレクトリ配列位置 | 暗号化長 |
| --- | --- | --- | --- | --- |
| 64 ビット Layout A（マーカーあり） | `info[3] + 0x40` | `+0x40` | `+0x50` | `144`（`0x90`）バイト |
| 64 ビット Layout B（マーカーなし） | `info[3] + 0x20` | `+0x20` | `+0x30` | `144`（`0x90`）バイト |
| 32 ビット Layout A | `info[3] + 0x40` | `+0x40` | `+0x50` | `144`（`0x90`）バイト |
| 32 ビット Layout B（標準シェル） | `info[3] + 0x10` | `+0x20` | `+0x30` | `0x290` バイト |
| 32 ビット Layout B（コンパクトシェル） | `info[3] + 0x10` | `+0x30` | `+0x40` | `0x290` バイト |

* **バリアント判定：** 64 ビットのマーカーありビルドでは、エントリポイント候補の直後にある復号済み dword が `ImageBase` と一致するかどうかを調べます。32 ビットビルドでは、復号した `u32@(info[3] + 0x10) > 0x10000` のときに Layout B を選択します（コンパクト `tbl` シェルでは `+0x30` / `+0x40` を使用）。専用 64 ビット DLL では代わりに `info[3] + 16` にある 656 バイトの `byte_rotate2` ブロックを読み取ります（`+0x10` が `EntryPoint`、`+0x20` がデータディレクトリ配列）。
* **一時復号と書き戻し：** このブロックを復号して `AddressOfEntryPoint` を `pe + 40` に、128 バイトのデータディレクトリ配列を `pe + 136`（PE32+）または `pe + 0x78`（PE32）にコピーした後、ローダー作業領域を元のバイト列に保つため `info[3]` 側のブロックを**暗号化バイト列へ書き戻します**。
* **マネージドイメージのゼロエントリポイント：** マネージドアセンブリでは、このブロック内の `AddressOfEntryPoint` に `0` が格納されています。64 ビットのマーカーありビルドおよび 32 ビットビルドでは、復号値が `0` のとき外側 PE ヘッダーが持つ `_CorExeMain` / `_CorDllMain` スタブのエントリポイントを維持します。一方、マーカーなし 64 ビットビルドおよび専用 64 ビット DLL ビルドでは `0` をそのまま書き込みます（純 IL のマネージド DLL として有効な形式です）。

## `.bss` ゼロ充填チェーン

圧縮セクションブロックから省かれた未初期化領域は、`byte_rotate2` で暗号化された 16 バイト単位の別チェーン `{dst, size}`（64 ビットでは 2 本目の `walk4` チェーン、32 ビットではクラスターの `+0x48`、専用 64 ビット DLL では末尾のチェーン）で指定されます。これらの範囲は 64 ビットビルドではセクション展開後に、32 ビットビルドではセクション展開前にゼロクリアされます。
