# PE32・DLL・マーカーなしレイアウト

{% tabs %}
{% tab title="PE32（標準・コンパクト）" %}
32 ビット（`0x10B`）バイナリは、ビルド別のステージサイズ差分 `ss_shift` をパラメーターとする 8 段のステージ連鎖（`SecondStage` から `EighthStage`）を実行します。確認されているビルドには 2 種類の `tbl` レイアウトが存在します（また、旧世代のコンパクトシェルでは `payload_xor_chain` が `info[5]` のペイロード全体を暗号化している場合があります）。

| 構造 / オフセット | 標準 PE32（`match - 0x88`） | コンパクト PE32（`match - 0x78`） |
| --- | --- | --- |
| `tbl` 内の `info[6]` 一致位置 | `tbl + 0x88` | `tbl + 0x78` |
| ヘッダーチェックサム記述子配列 | `tbl + 0x58` | `tbl + 0x50` |
| `SecondStage` の `(offset, size)` | `tbl + 0x98` | `tbl + 0x88` |
| `first_stage_cs` / `second_stage_cs` | `tbl + 0xA8` / `tbl + 0xB0` | `tbl + 0x98` / `tbl + 0xA0` |
| 退避された Import RVA | `tbl + 0xBC` | `tbl + 0xAC` |
| 退避された Resource `(RVA, size)` | `tbl + 0xC8` / `tbl + 0xCC` | `tbl + 0xB0` / `tbl + 0xB4` |
| ビルド別のステージバイアス `ss_shift` | `ss_size - 0xBC0` | `ss_size - 0xAEC` |
| `SevenStage` シード（`seven_key`） | `~u32@(cs1_addr + cs1_size - 0x10)` | `~u32@(cs1_addr + cs1_size - 0x0C)` |

コンパクト PE32 では、`SecondStage` 内部のポインター位置も `third_pair_off = 0xAB4 + ss_shift`、および `forth_key_off / third_key_off / cs_base_off / dp_base_off = 0x94C / 0x950 / 0x954 / 0x9C4 + ss_shift` に変化します。

* **ヘッダーチェックサムと DLL の `BaseReloc` 試行：** `header_checksum` はパック前の PE ヘッダー領域群に対する `calculate_checksum` を XOR 合成します。ネイティブ PE32 DLL では、パック前のヘッダーでゼロだった `DD[5]`（`BaseReloc`）にパッカーが値を設定するため、そのままのヘッダーと `DD[5]` をゼロクリアしたコピーの両方を試行し、`ThirdStage` の検証を通過した方を採用します。
* **`ThirdStage` の右ローテート幅（`shift`）総当たり：** 情報テーブルのシグネチャ（`1` / `0x11` に続いてイメージ内アドレスを持つ `2` が現れる並び）が見つかるまで、`xor_ror_dwords` の右ローテート幅を `[19, 21, 17, 23, 15, 25, 13, 11]` の順に試行します。4 つの `key_offsets` はその `0x58` バイト手前に配置されています。
* **動的な `advance_key` ラウンド数（`Fourth` / `Fifth` / `Seventh` / `Eighth`）：** 固定ラウンド数の代わりに、`dp_base` と `dp_base + 0x80` にある各 4 スロットのテーブル先頭から有効な 16 バイト補助記述子（`size > 4`、最初の空スロットで打ち切り）の個数を数えてラウンド数とします。
* **`EighthStage` の鍵とクラスター探索：** ギャップヒューリスティックと非印字 dword スキャンから `EighthStage` のシード候補を集め、ハフマン展開が正常に完了するかどうかで検証します。`EighthStage` 内部の設定クラスターには、`+0x18` にインポート、`+0x30` に `fileCS`、`+0x40` にセクション記述子、`+0x48` にゼロ充填範囲が格納されています（スタンプ `0x00007679` があるビルドではそれを基準とし、スタンプがないビルドでは `info[3]` 直後を指す `fileCS` ポインターの形状を基準に位置を特定します）。バイトコードスタブ 2 は最初の圧縮セクションブロックを試行展開して検証し、最終出力では RVA バッファーを `0x200` ファイルアライメントの配置へ詰め直します。
{% endtab %}

{% tab title="専用 64 ビット DLL" %}
旧世代の専用 64 ビット DLL（`0x20B` のみ）はアンカースキャンを行わず、固定オフセット `anchor = info[6] + 5592`（`0x15D8`）に設定ブロックを配置します。

| `anchor` からのオフセット | 内容 |
| --- | --- |
| `+4` / `+8` | Import Directory のサイズ / RVA |
| `+20` | 1 次ステージ記述子の鍵 |
| `+40` / `+44` | Resource Directory の RVA / サイズ |
| `+48` / `+56` | `checksum2` / `checksum1` 記述子 |
| `+120` | 1 次ステージ記述子（右ローテート幅 `21`） |
| `+184` | `xor_acc` チェックサム記述子リスト |

1 次テーブル（`addr1`）を基準として、2 次テーブルが `+3632`（右ローテート幅 `19`、鍵は `+3444`）、再配置 / コピーブロックが `+9248`、4 つの `key_offsets` が `+9160`、コードブロック 1..4 が `+3712 / +3728 / +3760 / +3840`、バイトコードスタブ 1 が `addr4 + 3200`、`metadata` が `addr5 + 12312`、バイトコードスタブ 2 が `metadata + 88`（`addr5 + 12400`）、セクション記述子配列が `addr5 + 11976` にそれぞれ配置されます。

* **セクション記述子：** `{dest, size, src, decompressed_size}` 形式で、`section_image_base = 4095 - u32@0x1080` を基準とし、`size != decompressed_size` の場合に展開を行います。
* **656 バイトのヘッダーメタデータ（`info[3] + 16`）：** `byte_rotate2` で復号します。`+0x10` の `EntryPoint` と `+0x20` の 128 バイトのデータディレクトリ配列を、それぞれ `pe + 40` と `pe + 136` へコピーします。
* **マネージド DLL の事前コピー：** この系統のマネージドアセンブリでは、セクションブロックが IL メソッド本体を上書きする前に、保護済みファイルから CLR を含むセクションをあらかじめコピーしておき、セクション展開後に `COR20` ヘッダーを再オーバーレイします。
{% endtab %}

{% tab title="マーカーなし 64 ビット" %}
新世代の 64 ビット EXE / DLL シェルでは、Stage 5 から `"pm\0\0cm\0\0"` と `0x40000000, 1` の両方のマーカーが省かれています。

1. **1 バイト刻みの LFSR スキャン：** Stage 5 全体から有効な 96 バイトのバイトコードスタブ候補をすべて収集します。ヒット後も `+1` バイトずつ進めることで、本物のスタブの直前に偶然有効な命令列としてパースできる箇所があっても読み飛ばさないようにします。
2. **`fileCS` 近傍度による順位付け：** 各候補スタブの `block - 0x58`（`fileCS`）を調べ、指す RVA が `info[3]` より後ろ（`rva > info[3]`）で `info[3]` との差分が最小のものから優先的に評価します。
3. **記述子テーブルのプローブ：** 候補スタブ周辺のポインタースロットを非破壊の `trial_byte_rotate2` で検査し、参照先が有効な `{src, src_len, dst, plain_len}` セクション記述子配列として解釈できるものを探します。
4. **圧縮ブロックによる試行検証：** 最初の圧縮セクションブロックに対してコピー -> AES 復号 -> バイトコードスタブ変換 -> `decompress` を試行実行し、正常に展開できたスタブとテーブルの組だけを採用します。

マーカーなしビルドは `walk3` を持たず、`.text` ページスクランブルの復元後に `walk5` ではなく `DD[1]`（`IMAGE_IMPORT_DESCRIPTOR` 配列）からインポートテーブルを復号します。また、一時復号される EP / データディレクトリブロックには Metadata Layout B を使用し、ASLR フラグと `DD[5]` のベース再配置を保持し、`.text` 内の平文 CLR テーブルを破壊しないよう `.text` の `dd8` 処理が完了した後に CLR メタデータを復元します。
