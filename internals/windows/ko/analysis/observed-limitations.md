# 관찰된 구조적 한계

여러 Windows 빌드 계열에 걸친 정적 분석과 실제 실행 테스트에서 재현 가능한 여덟 가지 아키텍처상의 한계가 확인됩니다.

* **접두사만 비교하는 VM 레지스트리 매칭 (`A09` 및 `540`):** `A09`는 세 개의 BIOS/시스템 레지스트리 값에서 벤더 문자열로 시작하는지(접두사 일치)만 확인하므로 식별자가 `SystemBiosVersion` 끝에 오는 하이퍼바이저나 `SMBIOS.reflectHost = "TRUE"` 구성을 놓치며, `540`은 `monitor_control.restrict_backdoor = "TRUE"` 설정만으로 비활성화됩니다.
* **평문 `%temp%` 디버그 로그 기능:** `%temp%` 하위에 12자리 16진수 폴더를 생성해 두기만 하면 상용 로더가 직접 단계 번호, 모듈 주소, 누락된 임포트, 후킹된 API, `AAA-BBB-CCC` 실패 위치 코드를 평문으로 기록합니다.
* **프로세스 내부에서 처리되는 온디맨드 페이지 복호화:** `HtdpStub2.dll`의 `KiUserExceptionDispatcher` 훅은 프로세스 내부의 어느 스레드에서 접근 위반 예외가 발생하든 해당 페이지를 복호화합니다. 따라서 각 페이지에 고의로 접근 예외를 발생시켜 복호화를 유도하고 선택적 `scribble` 마스크를 해제하면 실행 섹션 전체를 평문으로 확보할 수 있습니다.
* **구형 커널 드라이버의 공격 표면:** 1세대(`HtsysmNT`)는 인증 없는 Ring-0 셸코드 실행을 노출하며, 2세대(`Htsysm7679`)는 `offset < 0x1000` 범위의 `EPROCESS` 마스크 쓰기 IOCTL을 역연산 가능한 PID 암호만으로 보호하므로 서명된 드라이버 빌드가 BYOVD 공격 수단으로 악용될 수 있습니다. 3세대(`0xAA02` `ObRegisterCallbacks`)만이 유저모드 호출자에게 권한 상승 경로를 노출하지 않습니다.
* **외부 키 없는 자체 완결형 체크섬 체인:** 모든 암호 스케줄, 허프만 테이블, 바이트코드 스텁이 컨테이너 내부에 포함되고 각 단계 키는 외부 비대칭 키 없이 표준 CRC-32와 결정론적 산술 연산만으로 유도되므로, 페이로드를 수정하더라도 후속 단계 키를 다시 계산해 맞출 수 있습니다.
* **위장 가능한 `A03` 및 `A11` 프로세스 표식:** `A03`은 부모 실행 파일 이름(`explorer.exe` / `cmd.exe`)만 확인하며, `A11`은 암호학적 호스트 인증 대신 `peC` 섹션 이름이나 대소문자가 일치하는 `KeRnEl32.dLl` 임포트 문자열만으로 CrackProof 호스트 EXE 여부를 판별합니다.
* **짧은 인메모리 호스트 스탬프:** 로드 이후 호스트 이미지의 추가 바이트 마커를 확인하는 빌드도 호스트 코드 전체를 해싱하지 않고 고정된 소수의 바이트만 검사합니다.
* **제한적인 유저모드 안티디버깅 범위:** 실제 캡처 결과 상용 `410`/`520` 단계는 `IsDebuggerPresent`와 `NtQueryInformationProcess`에 의존하며(상용 `410` 내부에는 SEH 안티디버깅 하위 단계가 없음), `A0F` 역시 흔히 쓰이는 인젝션 DLL 이름의 고정 목록만 스캔합니다.
