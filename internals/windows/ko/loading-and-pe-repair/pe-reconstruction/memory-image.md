# 헤더, 섹션 및 0 채우기 범위

CrackProof는 섹션 바이트를 암호화할 뿐 아니라 PE 헤더의 주요 필드(`AddressOfEntryPoint`, 일부 `IMAGE_DATA_DIRECTORY` 항목, 섹션 원시 포인터)를 지우거나 다른 위치로 바꾼 뒤 프로세스 시작 시점에 메모리에서 복원합니다.

## RVA 매핑 섹션 헤더와 32비트 파일 밀착 배치

64비트 출력 이미지(및 32비트 작업 버퍼 복구 단계)에서는 파일 오프셋과 RVA가 일치하도록 섹션 헤더를 메모리 레이아웃 기준으로 정규화합니다.

* `SizeOfRawData = VirtualSize`
* `PointerToRawData = VirtualAddress`

32비트(`PE32`) 출력에서는 마지막 밀착 배치(`compaction`) 패스를 거쳐 이 RVA 버퍼를 디스크 정렬 형태의 PE 파일로 다시 구성합니다. 헤더 끝은 `0x400`에 맞추고, 각 섹션은 끝부분의 0 패딩을 잘라낸 `SizeOfRawData` 크기로 `0x200`(`FileAlignment`) 경계에 맞춰 순차 배치하며, 이에 따라 `SizeOfHeaders`와 `FileAlignment` 필드도 함께 갱신합니다.

## 엔트리 포인트 및 데이터 디렉터리 블록의 일시 복호화

`AddressOfEntryPoint`와 16개의 `IMAGE_DATA_DIRECTORY` 항목(128바이트)은 `info[3]` 부근에 `byte_rotate2`로 암호화된 채 저장되어 있습니다.

| 계열 및 변종 | 블록 시작 위치 | 엔트리 포인트 오프셋 | 디렉터리 오프셋 | 암호화된 길이 |
| --- | --- | --- | --- | --- |
| 64비트 레이아웃 A (마커) | `info[3] + 0x40` | `+0x40` | `+0x50` | `144` (`0x90`)바이트 |
| 64비트 레이아웃 B (마커리스) | `info[3] + 0x20` | `+0x20` | `+0x30` | `144` (`0x90`)바이트 |
| 32비트 레이아웃 A | `info[3] + 0x40` | `+0x40` | `+0x50` | `144` (`0x90`)바이트 |
| 32비트 레이아웃 B (표준 셸) | `info[3] + 0x10` | `+0x20` | `+0x30` | `0x290`바이트 |
| 32비트 레이아웃 B (컴팩트 셸) | `info[3] + 0x10` | `+0x30` | `+0x40` | `0x290`바이트 |

* **변종 판별:** 64비트 마커 빌드는 복호화된 엔트리 포인트 후보 직후의 dword가 `ImageBase`와 일치하는지 확인하여 레이아웃을 구분합니다. 32비트 빌드는 복호화된 `u32@(info[3] + 0x10) > 0x10000`일 때 레이아웃 B를 선택합니다(컴팩트 `tbl` 셸에서는 `+0x30` / `+0x40` 사용). 전용 64비트 DLL은 이와 달리 `info[3] + 16` 위치의 656바이트 `byte_rotate2` 블록(`+0x10`에 `EntryPoint`, `+0x20`에 데이터 디렉터리)을 읽습니다.
* **일시 복호화 후 원상 복구:** 해당 블록을 복호화해 `AddressOfEntryPoint`를 `pe + 40`에, 128바이트 데이터 디렉터리를 `pe + 136`(PE32+) 또는 `pe + 0x78`(PE32)에 복사한 뒤, 로더 작업 공간이 원래 바이트 상태를 유지하도록 **`info[3]` 부근 블록을 다시 암호문 바이트로 되돌립니다**.
* **관리형 이미지의 엔트리 포인트 0 처리:** 관리형 어셈블리는 이 블록에 `AddressOfEntryPoint` 값으로 `0`을 저장합니다. 복호화된 값이 `0`일 때 64비트 마커 빌드와 32비트 빌드는 외곽 PE 헤더에 있는 `_CorExeMain` / `_CorDllMain` 스텁 엔트리 포인트를 그대로 유지하며, 마커리스 64비트 빌드와 전용 64비트 DLL 빌드는 `0`을 직접 기록합니다(순수 IL 관리형 DLL에서 유효한 값).

## `.bss` 0 채우기 체인

압축된 섹션 블록에서 제외된 미초기화 데이터 구간은 별도의 16바이트 `byte_rotate2` 암호화 `{dst, size}` 체인(64비트의 두 번째 `walk4` 체인, 32비트의 클러스터 `+0x48`, 전용 64비트 DLL의 후미 체인)으로 전달됩니다. 64비트 빌드에서는 섹션 압축 해제 이후에, 32비트 빌드에서는 섹션 압축 해제 이전에 해당 범위를 0으로 채웁니다.
