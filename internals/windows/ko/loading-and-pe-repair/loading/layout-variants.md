# PE32, DLL 및 마커리스 레이아웃

{% tabs %}
{% tab title="PE32 (표준 및 컴팩트)" %}
32비트(`0x10B`) 컨테이너는 빌드별 스테이지 크기 편차인 `ss_shift`를 매개변수로 삼아 `SecondStage`~`EighthStage`로 이어지는 총 8단계 체인을 실행합니다. 실제 빌드에서는 두 가지 `tbl` 레이아웃이 관찰되며, 구형 컴팩트 셸 일부는 `payload_xor_chain` 단계에서 `info[5]` 페이로드 전체를 암호화합니다.

| 구조체 / 오프셋 | 표준 PE32 (`match - 0x88`) | 컴팩트 PE32 (`match - 0x78`) |
| --- | --- | --- |
| `tbl` 내부 `info[6]` 일치 위치 | `tbl + 0x88` | `tbl + 0x78` |
| 헤더 체크섬 디스크립터 배열 | `tbl + 0x58` | `tbl + 0x50` |
| `SecondStage` `(offset, size)` | `tbl + 0x98` | `tbl + 0x88` |
| `first_stage_cs` / `second_stage_cs` | `tbl + 0xA8` / `tbl + 0xB0` | `tbl + 0x98` / `tbl + 0xA0` |
| 보존된 임포트 RVA | `tbl + 0xBC` | `tbl + 0xAC` |
| 보존된 리소스 `(RVA, size)` | `tbl + 0xC8` / `tbl + 0xCC` | `tbl + 0xB0` / `tbl + 0xB4` |
| 빌드별 스테이지 편차 `ss_shift` | `ss_size - 0xBC0` | `ss_size - 0xAEC` |
| `SevenStage` 시드 (`seven_key`) | `~u32@(cs1_addr + cs1_size - 0x10)` | `~u32@(cs1_addr + cs1_size - 0x0C)` |

컴팩트 PE32는 `SecondStage` 내부 포인터 오프셋도 함께 이동하여 `third_pair_off = 0xAB4 + ss_shift` 및 `forth_key_off / third_key_off / cs_base_off / dp_base_off = 0x94C / 0x950 / 0x954 / 0x9C4 + ss_shift` 위치를 사용합니다.

* **헤더 체크섬 및 DLL `BaseReloc` 시험 검증:** `header_checksum`은 패킹 이전의 PE 헤더 영역들에 대해 `calculate_checksum` 결과를 XOR 누적합니다. 네이티브 PE32 DLL은 패킹 전에 0이었던 `DD[5]`(`BaseReloc`) 항목을 패커가 채워 넣기 때문에, 복구 시에는 현재 헤더 그대로 계산한 값과 `DD[5]`를 0으로 비운 사본으로 계산한 값을 모두 시험하여 `ThirdStage` 검증을 통과하는 쪽을 채택합니다.
* **`ThirdStage` 시프트 전수 대입:** 정보 테이블 시그니처(`1` 또는 `0x11` 뒤에 이미지 범위 내 주소를 가진 `2`가 이어지는 패턴)가 나타날 때까지 비트 회전 수 후보 `[19, 21, 17, 23, 15, 25, 13, 11]`을 순서대로 대입합니다. 4개의 `key_offsets`는 이 지점보다 `0x58`바이트 앞에 위치합니다.
* **동적 `advance_key` 라운드 수 (`Fourth` / `Fifth` / `Seventh` / `Eighth`):** 고정된 라운드 수를 쓰는 대신 `dp_base` 및 `dp_base + 0x80`에 있는 4슬롯 테이블에서 선두의 활성 16바이트 보조 디스크립터 개수(`size > 4` 조건, 첫 빈 슬롯에서 중단)를 세어 라운드 수로 사용합니다.
* **`EighthStage` 키 및 클러스터 탐색:** 오프셋 간격 휴리스틱과 비출력 dword 스캔으로 `EighthStage` 시드 후보를 수집한 뒤 허프만 압축 해제가 정상 완료되는 후보를 선택합니다. `EighthStage` 내부 설정 클러스터는 임포트 테이블을 `+0x18`, `fileCS`를 `+0x30`, 섹션 디스크립터를 `+0x40`, 0 채우기 범위를 `+0x48`에 배치합니다(스탬프 `0x00007679`가 있는 빌드는 이를 기준점으로 삼고, 스탬프가 없는 빌드는 `info[3]` 직후를 가리키는 `fileCS` 포인터 형태를 기준점으로 삼음). 바이트코드 스텁 2는 첫 번째 압축 섹션 블록을 시험 압축 해제하여 검증하며, 최종 출력 단계에서는 RVA 기준 버퍼의 섹션들을 `0x200` 파일 정렬(`FileAlignment`)에 맞춰 재정렬합니다.
{% endtab %}

{% tab title="전용 64비트 DLL" %}
구형 전용 64비트 DLL(`0x20B` 전용) 계열은 앵커 스캔을 생략하고 고정 오프셋 `anchor = info[6] + 5592`(`0x15D8`)에 설정 블록을 둡니다.

| `anchor` 기준 오프셋 | 내용 |
| --- | --- |
| `+4` / `+8` | 임포트 디렉터리 크기 / RVA |
| `+20` | 1차 스테이지 디스크립터 키 |
| `+40` / `+44` | 리소스 디렉터리 RVA / 크기 |
| `+48` / `+56` | `checksum2` / `checksum1` 디스크립터 |
| `+120` | 1차 스테이지 디스크립터 (`ror32` `21`비트) |
| `+184` | `xor_acc` 체크섬 디스크립터 목록 |

1차 테이블(`addr1`)을 기준으로 2차 테이블은 `+3632`(`ror32` `19`비트, 키는 `+3444`), 재배치/복사 블록은 `+9248`, 4개의 `key_offsets`는 `+9160`, 코드 블록 1..4는 `+3712 / +3728 / +3760 / +3840`에 자리합니다. 또한 바이트코드 스텁 1은 `addr4 + 3200`, `metadata`는 `addr5 + 12312`, 바이트코드 스텁 2는 `metadata + 88`(`addr5 + 12400`), 섹션 디스크립터 배열은 `addr5 + 11976`에 위치합니다.

* **섹션 디스크립터:** `{dest, size, src, decompressed_size}` 구조와 `section_image_base = 4095 - u32@0x1080` 기준 오프셋을 사용하며, `size != decompressed_size`일 때 압축을 해제합니다.
* **656바이트 헤더 메타데이터 (`info[3] + 16`):** `byte_rotate2`로 복호화되며, `+0x10`에 `EntryPoint`, `+0x20`에 128바이트 데이터 디렉터리 배열이 들어 있습니다(각각 `pe + 40` 및 `pe + 136`으로 복사).
* **관리형 DLL 사전 채우기:** 이 계열의 관리형 빌드는 보호된 원본 파일에서 CLR 데이터가 속한 섹션을 작업 버퍼에 먼저 복사해 둔 뒤, 섹션 블록을 복구해 IL 메서드 본문 구간을 채워 넣고 마지막에 `COR20` 헤더를 다시 오버레이합니다.
{% endtab %}

{% tab title="마커리스 64비트" %}
최신 64비트 EXE 및 DLL 셸은 Stage 5에서 `"pm\0\0cm\0\0"` 문자열과 `0x40000000, 1` 마커를 모두 생략합니다.

1. **1바이트 단위 LFSR 스캔:** Stage 5 전체를 훑으며 유효한 96바이트 바이트코드 스텁 후보를 모두 수집합니다. 실제 스텁 바로 앞에서 우연히 유효한 명령어 시퀀스가 성립하더라도 실제 스텁을 건너뛰지 않도록, 후보를 찾은 뒤에도 `+1`바이트씩 전진하며 스캔합니다.
2. **`fileCS` 근접도 순위화:** 각 스텁 후보의 `block - 0x58`(`fileCS`)을 확인하여 `info[3]` 이후 가장 가까운 양수 RVA 거리를 갖는 후보부터 평가합니다.
3. **디스크립터 테이블 탐색:** 원본 버퍼를 변경하지 않는 `trial_byte_rotate2`로 후보 스텁 주변 포인터 슬롯을 검사하여, 대상 주소가 유효한 `{src, src_len, dst, plain_len}` 섹션 디스크립터 배열로 파싱되는지 확인합니다.
4. **압축 블록 실증 검증:** 첫 번째 압축 섹션 블록에 대해 복사 -> AES 복호화 -> 스텁 변환 -> `decompress` 전 과정을 시험 실행하여 정상 통과한 스텁/테이블 쌍만 채택합니다.

마커리스 빌드는 `walk3` 테이블을 생략하고, `.text` 페이지 스크램블을 먼저 복구한 뒤 `walk5` 대신 `DD[1]`(`IMAGE_IMPORT_DESCRIPTOR` 배열)을 따라가며 임포트를 복호화합니다. 또한 임시 EP/디렉터리 블록에 메타데이터 레이아웃 B를 사용하며, ASLR 플래그와 `DD[5]` 기준 재배치 정보를 그대로 유지하고, `.text` 내부의 평문 CLR 테이블이 손상되지 않도록 `.text` `dd8` 복구 이후에 CLR 메타데이터를 복원합니다.
