# 시작 시퀀스와 상태 보고

원본 프로그램 코드가 실행되기 전에 CrackProof는 호스트 스텁과 수동 매핑된 보조 모듈에 걸쳐 설정 가능한 초기화 파이프라인을 수행하며, 마지막에 상태 코드 `280`(OEP 점프)에서 원본 코드로 제어를 넘깁니다.

```mermaid
flowchart LR
    S200["200..210\n초기화 및 아키텍처"] --> P1["410..540\n1단계 검사"] --> KRN["C00..C04 / Bxx\nOS 및 Htsysm"]
    KRN --> ASEQ["Axx 시퀀서\n및 DLL A15"] --> PRE["5D0..5E2, 5C0\n사전 준비 및 DLL"]
    PRE --> DEC["610, [640], 655, 6E1\n복호화 및 재배치"] --> PG["800..840, 660\n또는 800, 830"]
    PG --> EX["[E20..E91]\n드라이버 검사"] --> OEP["280\nOEP로 점프"]
```

## 부팅 시퀀스와 상태 코드 <a href="#the-boot-sequence-and-status-codes" id="the-boot-sequence-and-status-codes"></a>

활성화된 각 단계는 12비트 16진수 상태 코드를 기록합니다.

| 코드 | 단계 |
| --- | --- |
| `200` / `210` | 로더 시작 / 호스트 아키텍처 검사 |
| `410` | 유저모드 안티디버깅 검사 (`IsDebuggerPresent`; 실제 캡처 결과 상용 `410` 내부에는 SEH 하위 단계가 없음) |
| `510` | 로더 메모리 범위에 대한 CRC-32 무결성 검사 |
| `520` / `52F` | `NtQueryInformationProcess` 디버그 검사 / 커널 디버거 검사 |
| `540` | VMware I/O 포트 백도어 프로브 및 CPU 기능 검사 |
| `560` / `561` | 섹션 복호화 준비 / 보조 모듈 선택 |
| `C00` | 최소 Windows 빌드 검사: 호스트 빌드와 최소 빌드 두 개의 `(0x01A00000 + build)` DWORD 값을 기록 |
| `C01` | 부팅 구성 검사 (`testsigning`, `disableintegritychecks`) |
| `C02` / `C03` / `C04` | `Htsysm` 서비스(`Htsysm7679`, `Htsysm767901` 또는 `Htsysm1B4001`) 설치 / 드라이버 초기화 / 콜백 등록 또는 `EPROCESS` 보호 프로세스 설정 및 API 후킹 |
| `A03` | 부모 프로세스 검사 (`explorer.exe` / `cmd.exe`) |
| `A09` | VM 하드웨어 및 BIOS 레지스트리 접두사 검사 |
| `A0F` | 인젝션된 DLL 스캔 |
| `A08` / `A04` | 디스크의 원본 `ntdll` / `kernel32` `.text` 영역 복사 (`A04`는 디스크 상의 시스템 DLL이 변조된 경우 실행 중단) |
| `A07` / `A01` | 예상치 못한 외부 스레드 강제 종료 / 외부 스레드가 남아 있으면 실행 중단 |
| `A11` | DLL 호스트 프로세스 검사 (호스트 EXE의 `peC` 섹션 또는 대소문자가 정확히 일치하는 `KeRnEl32.dLl` 임포트 확인) |
| `A15` | 호스트 검사 통과 후 `5D0` 다음에 기록되는 DLL 시퀀서 마커 (별도 검사 로직 없음, EXE에서는 기록되지 않음) |
| `B00` / `BD0` / `BE0` | 호환 OS 검사 / `C:\Windows\msc.log.log` 미존재 확인 / 구형 SoftICE 및 Syser 디바이스 검사 |
| `B21` / `BB0` | 구형 드라이버 보조 DLL 로드 (`HtsyskNT.dll` / `HtpecmNT.dll`) |
| `5D0` `552` `570` `590` `5B0` `5B1` `598` `5A0` `5E1` `5E2` | 복호화 사전 준비 단계 |
| `A06` / `5C0` | 후기 API 후킹 / 임포트된 런타임 DLL 로드 |
| `610` | 섹션 및 헤더 일괄 복호화 |
| `640` | 페이지 보호 설정 전 실행 페이지 일괄 복호화 |
| `655` / `6E1` | 베이스 재배치 적용 / 후미 섹션 설정 |
| `800` `810` `820` `840` | 페이지 보호 준비(`800`..`820`), `KiUserExceptionDispatcher` 후킹 및 `PAGE_NOACCESS` 설정(`840`) |
| `830` | 페이지 암호화를 사용하지 않는 네이티브 빌드의 페이지 설정 완료 (`800` -> `830`) |
| `660` | 페이지 보호 설정 이후 `280` 진입 전 인계 단계 |
| `E20` `E40` `E52`..`E59` `E55` `E91` | `1B40` 계열 빌드의 후기 무결성 검사 및 분석 드라이버 디바이스 검사 |
| `280` | 원본 엔트리 포인트(OEP)로 최종 점프 |

다중 모듈 캡처([샘플 디버그 로그](https://app.gitbook.com/s/XSPACE_REFERENCE_KO/sample-debug-logs) 참고)에서는 모듈별 설정 차이가 그대로 드러납니다. 페이지 암호화가 활성화된 호스트 EXE는 `610 -> 640 -> 655 -> 6E1 -> 800..840 -> 660 -> 280` 순서로 진행하는 반면, 같은 프로세스 내에서 일괄 복호화만 수행하는 네이티브 플러그인 DLL은 `610 -> 655 -> 6E1 -> 800 -> 830 -> 280` 순서로 진행합니다. `A` 계열 검사는 하나의 시퀀서가 모드 값에 따라 여러 패스에 걸쳐 디스패치합니다.

## 디버그 로그 <a href="#debug-logging" id="debug-logging"></a>

* **`%temp%\<12 hex>` 폴더 조건:** 보호된 각 모듈은 12자리 16진수 폴더 이름을 계산하며, `%temp%\<12 hex>` 폴더가 존재하고 생성 시각이 약 48시간 이내이면 로더가 평문 트레이스 파일(EXE는 `HHMMSSmmmE-...`, DLL은 `HHMMSSmmmD-...`)을 기록합니다. `CreateFileW`를 후킹하거나 브레이크포인트를 걸면 로더가 확인하는 경로를 즉시 파악할 수 있습니다.
* **`\\.\mailslot\ErrLog-Pec<4 hex>` 채널:** 별도의 진단 채널로, 12자리 16진수 로깅 키의 첫 16비트 워드로부터 `((key + 1) * 0x3039) mod 0x8003` 수식으로 `<4 hex>` 값을 유도합니다. 메일슬롯 리스너가 열려 있으면 `-- Version` 지점부터 롤링 XOR(`state = (derive(key) + 1)^2 ^ ~length; word ^= state; state = ror32(state + i, 7)`)로 마스킹된 보고서를 기록합니다.
* **`AAA-BBB-CCC` 종료 코드:** 두 채널 모두 마지막에 9자리 상태 코드를 기록하며 닫힙니다.
  * **`AAA` (10진수 3자리):** 정상 시작 시 `000`이며, 실패 시 104개 항목으로 구성된 스테이지 테이블에서 실패한 단계의 1 기반 10진수 인덱스입니다(예: `C03` -> `046`, `A09` -> `048`, `E91` -> `601`).
  * **`BBB` (대문자 16진수 3자리):** 실패한 단계 실행 중 최초로 기록된 하위 단계 코드입니다.
  * **`CCC` (대문자 16진수 3자리):** `BBB`가 아직 설정되기 전에 최초로 기록된 원인/오류 코드입니다(관찰된 예: `046-019-01F`, `048-012-002`, `601-000-008`).

{% hint style="info" %}
**메모리에서 상태 코드 호출 지점 찾기.** 로깅 헬퍼는 `ECX`에 패킹된 12비트 코드를 전달받으며, 하위 니블 태그로 단계 상태는 `1`(`(code << 4) | 1`, 예: `0xC01` -> `0xC011`), `CCC` 원인 코드는 `3`(`(code << 4) | 3`), `BBB` 하위 단계 코드는 `5`(`(code << 4) | 5`)를 사용합니다. 호스트 모듈 자체의 로더 섹션에는 핵심 부트스트랩 코드(`200`, `560`, `590`, `5A0`, `5E1`, `5E2`, `800`)만 존재하며(1단계 즉시값은 실행 후 지워짐), `410`/`510`/`520`/`540`, `Cxx`, `Axx` 즉시값은 수동 매핑된 보조 DLL(`HtpecIt`, `dm` 등) 내부에 위치합니다.
{% endhint %}
