# 启动序列与状态报告

受保护二进制的首个执行线程属于 CrackProof，而非程序。加载器沿固定管线行进：环境检查、反分析清扫、内核驱动与子模块设置，然后是[分阶段加载器](../loading-and-pe-repair/loading/)中的分阶段解密，再然后——可选地——把它刚解密的内容重新加密，最后才跳转到原始入口点（OEP）。本页描述在运行时观察到的这条管线。

## 启动序列与状态码

加载器以 12 位**状态码**报告进度，大致每阶段一个。列表并不完整——各阶段按构建可配置，因此任何给定二进制只显示其中一个子集：

| 代码    | 阶段                                             |
| ----- | ---------------------------------------------- |
| `200` | 启动                                             |
| `210` | 主机架构检查                                         |
| `52F` | 内核调试器检查                                        |
| `540` | VMware 后门探测（和/或 CPU 特性标志）                      |
| `C00` | OS 最低版本检查                                      |
| `C01` | 启动选项检查（`testsigning`、`disableintegritychecks`） |
| `C03` | 初始化较新 Htsysm 驱动                                |
| `C04` | 设置 Protected Process 标志；安装钩子                   |
| `A0F` | 注入 DLL 检查                                      |
| `A09` | 经硬件注册表字符串的 VM 检查                               |
| `A08` | 从磁盘拷贝干净的 ntdll/kernel32 代码到内存                  |
| `A04` | 同上，磁盘副本被补丁则中止                                  |
| `A07` | 终止注入线程                                         |
| `A01` | 发现注入线程则中止                                      |
| `A03` | 父进程检查（`cmd.exe` / `explorer.exe`）              |
| `A11` | 对 DLL：检查宿主进程（`peC` 节，或来自 `KeRnEl32.dLl` 的导入）   |
| `B00` | OS 兼容版本检查                                      |
| `B21` | 加载 `HtsyskNT.dll`（旧驱动路径）                       |
| `BD0` | 确保 `C:\Windows\msc.log.log` 不存在                |
| `BE0` | SoftICE/Syser 调试器检查                            |
| `BB0` | 加载 `HtpecmNT.dll`（旧驱动路径）                       |
| `5C0` | 加载运行时 DLL（缺失者记入日志）                             |
| `640` | 解密可执行页                                         |
| `655` | 重定位                                            |
| `840` | 安装异常处理钩子；重新加密可执行页                              |
| `280` | 跳转到 OEP                                        |

观察到的序列证实特性是按模块配置的：在一个作品中，宿主 EXE 记录 `640 … 840`（批量解密后接页重加密），而同一进程中的原生插件 DLL 从 `610`（节解密）直接到 `655`——只批量解密一次，从不做页加密。

## 调试日志

调试日志有一个固定的落盘条件：如果 `%temp%` 下存在某个特定文件夹，进程中的每个受保护模块在恢复时都会向其中写一份详细调试日志。文件夹名为 12 个十六进制字符，随可执行文件不同而不同；获知它最简单的办法是在 `CreateFileW` 上下断点或钩子。日志行携带上述状态码，偶尔还有自由文本诊断（缺失的 DLL 名、被钩函数列表、地址）。

第二个通道把加密日志发往 mailslot `\\.\mailslot\ErrLog-Pec<number>`。两个通道共享一种 9 位错误格式 `AAA-BBB-CCC`：失败时的恢复状态码、一个子阶段，以及第三个字段。

{% hint style="info" %}
**在二进制中定位阶段。** 状态码经由一个辅助函数写出，编码为 16 位值 `(code << 4) | 1`。在写日志处下断，然后在二进制中按字节搜索该字（例如 `0xC01` → `11 C0`），即可直接落在发出该阶段的代码上——这是已知的、给加载器代码建图的最快办法。
{% endhint %}
