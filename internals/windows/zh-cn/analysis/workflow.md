# 分析流程

{% stepper %}
{% step %}
## 捕获当前构建的 `%temp%` 调试日志

在进程启动初期对 `CreateFileW` 下断点或跟踪调用，观察其在 `%temp%` 下探测的 12 位十六进制目录名，手动创建该目录（创建时间须在约 48 小时以内）后重新运行目标程序。每个受保护的 EXE 与 DLL 都会输出逐阶段跟踪日志（`HHMMSSmmmE-...` / `HHMMSSmmmD-...`），并在末尾附上 `AAA-BBB-CCC` 结束状态码（参见 [启动流程与状态上报](../runtime/startup-status.md#the-boot-sequence-and-status-codes)）。
{% endstep %}

{% step %}
## 将状态码映射到宿主与辅助模块代码

日志辅助函数通过 `ECX` 接收一个 32 位打包值，其低 16 位按 `(code << 4) | 1` 编码阶段状态码，`| 3` 编码 `CCC` 原因码，`| 5` 编码 `BBB` 子阶段码。核心引导状态码（`200`、`560`、`590`、`5A0`、`5E1`、`5E2`、`800`）直接位于宿主模块的加载器节内（执行完毕后会被擦除），而 `410`/`510`/`520`/`540`、`Cxx` 与 `Axx` 立即数则位于手动映射的辅助 DLL（`HtpecIt.dll`、`dm` 等）内部。
{% endstep %}

{% step %}
## 区分多态干扰代码与真实阶段逻辑

* 跳过特征明显的保存全寄存器计时诱饵（`in eax, dx` 后紧跟零偏移的 `jne $+2`）以及置位 `TF`（`#DB`）的 SEH 陷阱，直接从初始化专用上下文寄存器的指令切入追踪。
* 遇到无条件跳转后填充垃圾字节导致静态反汇编失步时，可以磁盘原文件为后端模拟执行该阶段的文件读取与映射调用（`CreateFileW` / `MapViewOfFile`），或对同一构建族系的两个受保护模块做二进制比对，将随构建变化的数据表与共用的阶段代码分离开。
{% endstep %}

{% step %}
## 基于 VAD 转储按需页加密模块

* 解密后的页面位于私有内存中，转储时应按虚拟地址描述符（`VAD`）导出，而非从文件缓存提取。
* 到达 OEP（`280`）后按节检查页面驻留状态：一次性批量解密的模块（`800 -> 830`）此时所有可执行页面均已填充就绪，而开启按需页加密的模块（`640 -> 840`）中尚未执行到的页面仍处于 `PAGE_NOACCESS` 状态，需触发缺页后才会解密。
* 进程内辅助代码应安排在 `A07` 外部线程清理完成之后再介入；同时可对启动完成后相隔数秒采集的两份内存快照做差分比对，识别新触发解密的页面或正在生效的 `scribble` 二次涂抹。
{% endstep %}

{% step %}
## 对重建后的 PE 镜像做静态结构校验

确认还原出的 PE 文件有效前，应核对以下五项结构不变量：

1. `MZ` 与 `PE\0\0` 签名合法，可选头魔数为 `0x10B` 或 `0x20B`，且所有节表头均未越界。
2. 对于入口点非零的原生模块，`AddressOfEntryPoint` 落在内容非全零的可执行区间内（且 CRT 入口桩的 `call`/`jmp` 目标均留在 `.text` 节内）。
3. 在原生模块的最多前 256 个 `IMAGE_IMPORT_DESCRIPTOR` 中，模块名均可解码为可打印 ASCII 的 `.dll` / `.exe` 名称，按名称导入的 `IMAGE_IMPORT_BY_NAME` 字符串也均为可读 ASCII。
4. 对于托管程序集（`DD[14]` 非零），`COR20` 头部的 `cb == 0x48`，且引用的元数据根以 `BSJB` 开头。
5. 对于所有 DLL，`DataDirectory[5]`（`BaseReloc`）非零，且已置位 `DYNAMIC_BASE`（`0x0040`）。
{% endstep %}
{% endstepper %}
