# 头部、节表与零填充区间

除加密各节数据外，CrackProof 还会清空或重定向部分 PE 头部字段（`AddressOfEntryPoint`、特定 `IMAGE_DATA_DIRECTORY` 表项及各节原始文件指针），等进程启动时再在内存中动态还原。

## 按 RVA 映射的节表头与 32 位紧缩

在 64 位输出文件（以及 32 位工作缓冲区的恢复阶段）中，节表头统一规整为内存展开布局，使文件偏移直接等于 RVA：

* `SizeOfRawData = VirtualSize`
* `PointerToRawData = VirtualAddress`

在 32 位（`PE32`）输出文件中，最后会执行一轮文件紧缩，将该 RVA 缓冲区重新排布为紧凑的磁盘对齐 PE：头部结束于 `0x400`，各节按 `0x200`（`FileAlignment`）边界顺序紧排，裁去末尾零填充以收缩 `SizeOfRawData`，并同步更新 `SizeOfHeaders` 与 `FileAlignment`。

## 临时解密的入口点与数据目录块

`AddressOfEntryPoint` 与 16 个 `IMAGE_DATA_DIRECTORY` 表项（共 128 字节）存放在 `info[3]` 附近，由 `byte_rotate2` 加密：

| 族系与变体 | 数据块起点 | 入口点偏移 | 数据目录偏移 | 加密长度 |
| --- | --- | --- | --- | --- |
| 64 位布局 A（带标记） | `info[3] + 0x40` | `+0x40` | `+0x50` | `144`（`0x90`）字节 |
| 64 位布局 B（无标记） | `info[3] + 0x20` | `+0x20` | `+0x30` | `144`（`0x90`）字节 |
| 32 位布局 A | `info[3] + 0x40` | `+0x40` | `+0x50` | `144`（`0x90`）字节 |
| 32 位布局 B（标准壳） | `info[3] + 0x10` | `+0x20` | `+0x30` | `0x290` 字节 |
| 32 位布局 B（紧凑壳） | `info[3] + 0x10` | `+0x30` | `+0x40` | `0x290` 字节 |

* **变体识别：** 64 位带标记版本检查紧跟在候选入口点后面的解密双字是否等于 `ImageBase`；32 位版本在解密后的 `u32@(info[3] + 0x10) > 0x10000` 时选用布局 B（紧凑 `tbl` 壳改取 `+0x30` / `+0x40`）。专用 64 位 DLL 则读取 `info[3] + 16` 处 656 字节的 `byte_rotate2` 数据块（`EntryPoint` 位于 `+0x10`，数据目录位于 `+0x20`）。
* **临时解密与回写：** 先解密该数据块，将 `AddressOfEntryPoint` 拷贝至 `pe + 40`，并将 128 字节数据目录拷贝至 `pe + 136`（PE32+）或 `pe + 0x78`（PE32），随后**将 `info[3]` 处恢复为原始密文字节**，使加载器工作区保留原有字节内容。
* **托管镜像的零入口点：** 托管程序集在该数据块中记录的 `AddressOfEntryPoint` 为 `0`。在 64 位带标记版本和 32 位版本上，只要解密值为 `0`，重建流程就会保留外层 PE 头部原有的 `_CorExeMain` / `_CorDllMain` 桩入口点；64 位无标记版本和专用 64 位 DLL 版本则直接写入 `0`（对纯 IL 托管 DLL 合法）。

## `.bss` 零填充链表

未纳入压缩节数据块的未初始化内存区间，由另一条经 `byte_rotate2` 加密的 16 字节 `{dst, size}` 链表单独给出（64 位版本为第二条 `walk4` 链表，32 位版本位于配置簇 `+0x48`，专用 64 位 DLL 则位于尾部链表）。64 位版本在节数据解压之后将这些区间清零，32 位版本则在解压之前清零。
