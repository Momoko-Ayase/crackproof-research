# 结构定位与校验

由于各阶段体积随具体构建浮动（PE32 上的 `ss_shift`、64 位上的 `anchor_extra`），且较新的 64 位构建省去了固定的 Stage 5 特征标记，静态恢复流程在真正改写工作镜像前，会对每一个候选偏移、移位参数与种子逐项验证：

* **锚点与表项不变量：** 展开任何阶段描述符前，要求满足 `u32@anchor == info[3]`、Stage 2 `table_start` 处为 `(1, 0, info[3], 0)`，且 `{offset, size}` 落在镜像边界内。
* **字节码语法校验：** 将候选 96 字节 LFSR 槽位一直解析到 `0xC3`（`RET`），拒绝任何目标寄存器非 `AL` 的 `ModR/M` 编码（`mod != 3`、`rm != 0` 或 `reg > 1`）；若真实字节码桩前可能出现误匹配，扫描时按 1 字节步进。
* **只读描述符预检：** 用 `trial_byte_rotate2` 预解密候选指针目标，确认 `src + section_data_file_base` 与 `dst + plain_len` 均未超出文件大小和 `SizeOfImage`。
* **首个压缩块实测验证：** 绝不单凭原样拷贝块就采纳字节码桩或 `EighthStage` 种子；必须在首个压缩块上完整重放 AES 解密、字节码变换与 `decompress`，并要求输出满足 `written == plain_len` 且哈夫曼树遍历合法。
* **三级 `.text` 页混淆（`dd8`）判定：**
  1. 在 64 位镜像上，依次在 `unchanged`、`shift 0` 与 `shift 15` 三种模式下检查 18 字节 CRT 入口桩（`48 83 EC ib / E8 rel32 / 48 83 C4 ib / E9 rel32`），选取 `call` 与 `jmp` 目标均落在 `.text` 节内的唯一模式。
  2. 若未命中，在 64 位镜像上统计 `.text` 内部各页中 `0xC3`（`RET`）后跟 `>= 4` 个 `0xCC` 填充字节的连续段总长度，要求得分比未变换基线至少高出 `8`。
  3. 64 位镜像仅在所有 `RET + int3` 得分均为 `0` 时回退至此规则，32 位镜像则始终按此规则对比 `page + 1` 与 `0x8000 * (page + 1)`：统计变换后变为 `0xCC` 的改动位置数，要求同时达到基线的 2 倍以上（`>= 2x`）且命中数 `>= 8` 才改写 `.text`。

任一阶段若所有候选参数均未通过校验，恢复流程会直接报错终止，不会输出半解码状态的残损 PE。
