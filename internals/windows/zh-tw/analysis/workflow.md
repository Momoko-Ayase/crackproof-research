# 分析工作流程

{% stepper %}
{% step %}
## 擷取該組建專屬的 `%temp%` 除錯記錄

在行程啟動時對 `CreateFileW` 設中斷點或追蹤 API 呼叫，觀察載入器在 `%temp%` 下探測的 12 位十六進位字元資料夾名稱；建立該資料夾（建立時間戳記距今須在約 48 小時以內）後重新執行目標程式，所有受保護的 EXE 與 DLL 就會逐階段寫出明文追蹤檔（`HHMMSSmmmE-...` / `HHMMSSmmmD-...`），並以 `AAA-BBB-CCC` 狀態摘要收尾（參見[啟動流程與狀態回報](../runtime/startup-status.md#the-boot-sequence-and-status-codes)）。
{% endstep %}

{% step %}
## 將狀態碼對應至宿主與輔助模組程式碼

記錄輔助函式透過 `ECX` 接收一組打包後的 32 位元數值，其低 16 位元以 `(code << 4) | 1` 編碼階段狀態碼、以 `| 3` 編碼 `CCC` 原因碼、以 `| 5` 編碼 `BBB` 子階段碼。核心引導狀態碼（`200`、`560`、`590`、`5A0`、`5E1`、`5E2`、`800`）在執行後抹除前可直接於宿主模組自身的載入器區段內找到；而 `410` / `510` / `520` / `540`、`Cxx` 與 `Axx` 立即值則位在手動映射的輔助 DLL（`HtpecIt.dll`、`dm` 等）內部。
{% endstep %}

{% step %}
## 區分多態花指令與真實階段邏輯

* 跳過保存全部通用暫存器的計時干擾片段（`in eax, dx` 後接位移量為零的 `jne $+2`）以及設定 `TF`（`#DB`）的 SEH 陷阱，改從實際初始化脈絡暫存器的指令開始追蹤。
* 當無條件跳轉後方夾帶的花指令位元組打亂靜態反組譯同步時，可在模擬器中將檔案 I/O（`CreateFileW` / `MapViewOfFile`）導向磁碟原檔以模擬執行該階段，或比對同一組建家族的兩個受保護模組，將隨組建變動的資料表與共用的階段程式碼分離開來。
{% endstep %}

{% step %}
## 橫跨 VAD 傾印分頁加密模組

* 已解密分頁存放在私有記憶體中，傾印時應使用虛擬位址描述元（`VAD`）擷取工具，而非檔案快取擷取工具。
* 抵達 OEP（`280`）後檢查各區段的分頁保護狀態：整批解密模組（`800 -> 830`）的所有可執行分頁當下即已全數解密；啟用分頁保護的模組（`640 -> 840`）則會讓尚未執行到的分頁維持 `PAGE_NOACCESS`，直到觸發存取違規例外時才隨選解密。
* 若要在行程內掛載輔助傾印邏輯，請排在 `A07` 清除外來執行緒之後再啟動；同時可擷取相隔數秒的兩份啟動後快照互相比較，藉此觀察新觸發解密的分頁，或確認是否有啟用 `scribble` 重新遮蔽機制。
{% endstep %}

{% step %}
## 靜態驗證重建後的 PE 映像

採信還原出的 PE 檔案前，請先確認以下五項結構不變條件：

1. 具備合法的 `MZ` 與 `PE\0\0` 簽章、選用標頭魔數為 `0x10B` 或 `0x20B`，且所有區段標頭皆未超出邊界。
2. 針對進入點非零的原生模組，`AddressOfEntryPoint` 必須落入非全零的可執行區間（且 CRT 進入點 stub 的 `call` / `jmp` 目標皆留在 `.text` 內）。
3. 檢查原生模組最多前 256 筆 `IMAGE_IMPORT_DESCRIPTOR`：模組名稱須解碼為可列印 ASCII 的 `.dll` / `.exe` 名稱，且依名稱匯入的 `IMAGE_IMPORT_BY_NAME` 字串皆為可讀 ASCII。
4. 針對受控組件（`DD[14]` 非零），`COR20` 標頭的 `cb == 0x48`，且其參照的中繼資料根結構（Metadata Root）開頭為 `BSJB`。
5. 針對所有 DLL，`DataDirectory[5]`（`BaseReloc`）非零，且已設定 `DYNAMIC_BASE`（`0x0040`）。
{% endstep %}
