# 結構探測與驗證

各組建的階段大小會隨版本浮動（PE32 為 `ss_shift`，64 位元為 `anchor_extra`），且新版 64 位元組建不再保留固定的第 5 階段特徵標記；因此靜態還原必須先逐一驗證所有候選偏移量、位移值與種子，確認無誤後才寫入工作映像：

* **錨點與資料表不變條件：** 解開任何階段描述元之前，必須滿足 `u32@anchor == info[3]`、第 2 階段 `table_start` 處為 `(1, 0, info[3], 0)`，且 `{offset, size}` 範圍完全落在映像界限內。
* **嚴格的位元組碼 VM 語法檢查：** 將每個 96 位元組的候選 LFSR 槽位一路剖析至 `0xC3`（`RET`），凡遇到非 `AL` 的 `ModR/M` 編碼（`mod != 3`、`rm != 0` 或 `reg > 1`）一律剔除；在真實 stub 前方可能出現誤判的位置，改為每次前進 1 位元組逐一掃描。
* **非破壞性描述元預檢：** 先以 `trial_byte_rotate2` 檢視候選指標目標，確認 `src + section_data_file_base` 未超出檔案大小，且 `dst + plain_len` 未超出 `SizeOfImage`。
* **首個壓縮區塊實測驗證：** 絕不只憑原樣複製（raw-copy）區塊就採信位元組碼 stub 或 `EighthStage` 種子；必須對第一個壓縮區塊實際跑完 AES、位元組碼轉換與 `decompress`，確認霍夫曼樹走訪合法且 `written == plain_len`。
* **三層式 `.text` 分頁打亂（`dd8`）模式判定：**
  1. 在 64 位元映像上，先針對 `unchanged`、`shift 0` 與 `shift 15` 三種模式檢查 18 位元組的 CRT 進入點 stub（`48 83 EC ib / E8 rel32 / 48 83 C4 ib / E9 rel32`）；若僅有單一模式能讓 `call` 與 `jmp` 目標同時落在 `.text` 區段內，即採用該模式。
  2. 否則在 64 位元映像上，統計 `.text` 內部分頁中 `0xC3`（`RET`）後接 `>= 4` 個 `0xCC` 填補位元組的連續總長度，且分數必須比未變動基準值高出至少 `8`（正差值 `>= 8`）。
  3. 唯有在 64 位元上所有 `RET + int3` 得分皆為 `0` 時（以及 32 位元上比較 `page + 1` 與 `0x8000 * (page + 1)` 時），才退回統計變動位置轉為 `0xCC` 的數量，且必須同時達到基準值的 `>= 2x` 與 `>= 8` 次命中，才會實際修改 `.text`。

只要任一階段的所有候選值皆未通過驗證，還原流程就會直接報錯中止，絕不輸出解碼不完整的 PE 檔案。
