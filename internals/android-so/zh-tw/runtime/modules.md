# 運行時模塊

下列命令標識來自第二階段記錄。職責取自這些模塊物化之後運行的函數。ELF 恢復所需的標識仍在[模塊記錄流](../restoration/module-streams.md)。

標成“尚未化約”的標識作為記錄出現過，其行為還沒有寫成穩定說明。

## 解釋器與移交

| 標識 | 職責 |
| --- | --- |
| `0xE2`–`0xE8` | 嵌套記錄流解釋器。`0xE2` 就是第二階段自身 |
| `0xF3`–`0xF8` | 交給下一層解釋器的直接數據對象 |
| `0xD0` | 第一階段移交的文件尾映射 |
| `0x98` | 最終移交：複製恢復後的鏡像並調用 `.init_array`。對應 Windows 狀態 `280` |

## 恢復

| 標識 | 職責 |
| --- | --- |
| `0x9B` | 恢復工作流：頁權限，消費 `0x9D` 和 `0x9E` |
| `0x9D` | 受保護容器：描述符、分段、寫入流 |
| `0x9E` | 隱藏的動態符號補丁（`dynsym` / `dynstr`） |
| `0xB9` | 與元數據相關的數據。在 IL2CPP 庫上是真實載荷；在部分原生庫上為空或無數據 |
| `0x0C` | 僅 IL2CPP。把 `mmap` 換成掛鉤，在映射 `global-metadata.dat` 時恢復方法令牌。見[方法令牌](../metadata/method-tokens.md) |

## 環境與完整性

| 標識 | 職責 |
| --- | --- |
| `0x81` | 解密庫名和符號，`dlopen` / `dlsym`，緩存函數指針 |
| `0x96` | 按 16 字節塊變換的通用解密器 |
| `0x8F` | 讀 `/proc/self/cmdline`，查詢 uid/gid/tid，創建或複用環境 token，檢查路徑 owner 與 mode |
| `0x97` | 掃描 `/proc` 中同一 UID 的進程；寫代碼前 `mprotect`；啟動 detached 工作線程 |
| `0x02` | 向 UDP 123 查詢時間，再和配置閾值比較 |
| `0x69` | `fork` 子進程探測並等待退出狀態 |
| `0x60` | 掃描系統庫目錄、`/proc` 環境和運行時路徑 |
| `0x40` | 檢查 `base.apk` 及同目錄 split APK。簽名順序：v3.1，然後 v3，然後 v2，然後 JAR/v1 |
| `0x20` | 校驗目標路徑、ELF 頭、`/proc/self/maps` 和 libc 映射 |
| `0x33` | 構造 dex2oat 選項列表，並刪除不符合的產物 |
| `0x72` | Unix domain socket 的 `bind` / `listen` / `accept` |
| `0xB0` | 變換一張 sentinel 表 |

## 已出現，尚未化約

`0x8E`、`0x6A`、`0x68`、`0x54`、`0x71`、`0x53`、`0xA4`、`0x58`、`0x73`、`0xA0`、`0xB2`。

它們出現在與上表相同的解釋器層。會被登記，並且除非 `flags & 0x100`，否則會收到 init/entry 調用。除此之外函數尚未化約。
