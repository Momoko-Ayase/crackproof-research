# メソッドトークン

標準の IL2CPP メタデータファイルは、マジック値 `0xFAB11BAF` とそれに続く 32 ビットのバージョン番号で始まります。Android 版の CrackProof は、バージョン `29`・`31`・`39` ではイメージ（`Il2CppImage`）単位の `MethodDef` RID（`0x06000000 | rid`）に対して、バージョン `24`（`v24.1`）では 256 エントリの例外テーブルと組み合わせたグローバルな `methodIndex` エントリに対して、シード付きの 5 ラウンド反転・減算置換を適用します。なお、バージョン `31` の一部ビルドでは鍵を使わない `-GMD` メソッドトークン配置が使用されます。

鍵を使わずテーブルの並び順だけで疎なトークンを `0x06000000 | (local_index + 1)` に振り直す Windows 版 `-GMD` 方式との比較については、[IL2CPP メタデータの難読化](https://app.gitbook.com/s/XSPACE_WINDOWS_JA/analysis/il2cpp-metadata)を参照してください。

## 5 ラウンドの逆置換

連続する `count` 個のエントリ範囲（`count >= 2`）と 32 ビットの `seed` から、`key = (seed % (count // 2)) + (count // 4)` および `mirror = count * 2 - 1` を導出します。0 始まりの各オフセット `value`（`0 <= value < count`）は、符号なし 32 ビット演算のラップアラウンド（`MASK32 = 0xFFFFFFFF`）を用いた同一の 5 ラウンド処理で元の値へ戻せます。

```text
repeat 5 times:
    if value & 1:
        value = mirror - value
    value >>= 1
    if value >= count:
        value = mirror - value
    value = (value - key) & MASK32
    if value > count:
        value = (value + count) & MASK32
```

バージョン `29`・`31`・`39` の `MethodDef` メソッドトークンでは、各イメージの閉区間 RID 範囲 `[low, high]` 内で `value = rid - low` とし、復元後のトークンは `0x06000000 | (value + low)` となります。正規のメタデータはイメージごとに連番の RID `1..=count` をすでに持っているため、復元処理ではまず対象イメージが正規の並びかどうかを判定し、未保護の入力を書き換えないようにします。

## バージョン別のレイアウトとシード復元

{% tabs %}
{% tab title="バージョン 29・31" %}
バージョン `29` と `31` は固定オフセットのヘッダー `{offset, size}` ペアを使用し、型定義とイメージ記述子のレイアウトを共有しています。

* **型定義（`@0xA0`、ストライド `0x58`）:** `methodStart`（`+0x24` の `u32`）、`method_count`（`+0x40` の `u16`）。
* **イメージ（`@0xA8`、ストライド `0x28`）:** `typeStart`（`+0x08` の `u32`）、`typeCount`（`+0x0C` の `u32`）。
* **メソッド（`@0x30`）:**
  * **バージョン 29:** ストライド `0x20`、`token`（`u32`）は `+0x14`。
  * **バージョン 31:** ストライド `0x24`、`token`（`u32`）は `+0x18`。

実行時にはモジュール `0x0C` が `mmap` をフックし、埋め込まれたシード（確認されたビルドでの既定値は `0xA6FAE968`）を適用します。一方、バージョン `29`・`31`・`39` の静的復元ではモジュール `0x0C` を必要としません。各イメージが取り得る `key` の剰余候補は `count / 2` 通りに限られるため、出力が正規の連番 `1..=count` になる候補を探索し、複数イメージ間で `seed % (count / 2)` の制約条件の共通部分をとることで、`global-metadata.dat` 単体から有効なシードを復元できます。制約が付かないファイルでは既定値の `0xA6FAE968` を使用し、`-GMD` で保護されたバージョン `31` ビルドではテーブル順に基づく `0x06000000 | (local_index + 1)` の再割り当てを適用します。
{% endtab %}

{% tab title="バージョン 39（コンパクトディレクトリ）" %}
バージョン `39` では固定ヘッダーオフセットが廃止され、12 バイトの `{offset, size, count}` セクション記述子からなるコンパクトディレクトリと可変幅のテーブルインデックスに置き換わっています。

* `type_definition`、`parameter`、`generic_container` の各インデックス幅は、`count <= 255` なら `1` バイト、`count <= 65535` なら `2` バイト、`count > 65535` なら `4` バイトになります。
* `type_index` の幅はセクション `18`（`interface_offsets`）から算出され、`count == 0` のときは `4` バイト、それ以外は `(size / count) - 4` になります。

これら 4 つのインデックス幅からメソッド・型定義・イメージのレコードストライドとフィールドオフセットを算出すれば、以降は同じイメージごとの剰余探索と 5 ラウンド RID 逆置換がそのまま機能します。
{% endtab %}

{% tab title="バージョン 24.1（methodIndex + 0x0C）" %}
`v24.1` の `Il2CppMethodDefinition` レイアウト（ストライド `0x34`、`+0x14` に符号付き `i32` の `methodIndex`）に一致する外部バージョン `24` メタデータでは、`MethodDef` トークンは変更されず、非負の `methodIndex` エントリ全体（`0..active_count`、ただし `active_count > 256`）が置換されます。

1. 非負の `methodIndex` スロット全 `active_count` 個に対し、`key = (seed % (active_count // 2)) + (active_count // 4)` を用いた 5 ラウンド関数で置換が施されます。
2. 先頭 256 個の有効スロットの値は、モジュール `0x0C` 内の 256 エントリ `u32` 例外テーブルに別途退避されます。

そのため静的復元では、メタデータファイルを同一アプリケーションから展開したモジュール `0x0C` とペアにし、`0x0C` 内から `{u32 seed, u32 24}` と `{u32 1, u32 active_count - 1}` のヘッダーマーカーおよび 256 エントリの例外テーブルを特定します。まず 256 個の例外エントリを書き戻したうえで、全 `active_count` 個の有効メソッドにわたって 5 ラウンド置換を逆変換します。
{% endtab %}
{% endtabs %}

## 復元後の検証

再マッピング後、イメージ・型定義・メソッドの各テーブルがファイル範囲内に収まっていること、すべてのメソッドがいずれか 1 つのイメージに属し、イメージごとにテーブル上で連続して並んでいること、すべての `MethodDef` トークンがテーブルプレフィックス `0x06000000` と正規のローカル RID を持つこと（`v24.1` では `0..active_count` を網羅していること）、および範囲外や重複のエントリが残っていないことを検証します。
