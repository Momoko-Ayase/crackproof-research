# ランタイムモジュール一覧

Stage 2 の各レコードは、1 バイトの `command_id`（`0x00`..`0xFF`）でモジュールを登録します。静的復元で扱うのは[モジュールストリーム](../restoration/module-streams.md)に記載されたモジュール群であり、残りのモジュールはロード時の環境検査や補助処理を実行します。

## ストリームインタープリターとブートストラップスロット

| ID | 役割 |
| --- | --- |
| `0xE2`..`0xE8` | 多段レコードストリームのインタープリター（`0xE2` は復号された Stage 2 ルートイメージ） |
| `0xF3`..`0xF8` | `0xE3`..`0xE8` に入力として渡される直接ストリームスライス（`sid = command_id - 0x10`） |
| `0xD0` | Stage 2 開始時に `(X6, X7)` から登録される `SHT_LOUSER` ファイル末尾マッピング |

## イメージ・シンボル・コンストラクター・メタデータの復元

| ID | 役割 |
| --- | --- |
| `0x9B` | `Module9bConfig`（`header_seed`、`container_seed`、逆順 AES-256 ラウンド鍵、`skip_aes`）を保持する復元コーディネーター。対象セグメントとメモリ保護属性を復元します |
| `0x9D` | `0x5C` バイトの `ProtectedDescriptor`、主 `PT_LOAD` コンテナー、および補助 ELF コンテナー（再配置・シンボル）を保持する直接ペイロード |
| `0x9E` | 表層 ELF から削除された隠蔽 `.dynsym` シンボルと `.dynstr` 文字列 |
| `0x96` | 補助再配置のシンボルインデックスを逆置換するための `auxiliary_symbol_seed` を保持する 16 バイトブロック復号モジュール |
| `0x98` | 最終コンストラクターディスパッチャー。イメージ復元後に対象ライブラリの `.init_array` コールバックを解決・実行します（Windows 版のステータス `280` に相当） |
| `0x0C` | IL2CPP ビルド専用。`mmap` をフックしてロード時に `global-metadata.dat` の難読化を解除するほか、`v24.1` 用の `methodIndex` シードと 256 エントリの例外テーブルを内包します |
| `0xB9` | メタデータ関連の補助ブロブ（IL2CPP ビルドではデータが格納され、通常のネイティブライブラリでは省略または空） |

## 環境検査・シンボル解決・整合性ヘルパー

| ID | 役割 |
| --- | --- |
| `0x81` | ライブラリ名とシンボル名を復号し、`dlopen` / `dlsym` で関数ポインターを解決してキャッシュします |
| `0x8F` | `/proc/self/cmdline` の読み取り、`uid` / `gid` / `tid` の取得、環境トークンの管理、パスの所有者・パーミッション確認を行います |
| `0x97` | `/proc` から同一 UID のプロセスを走査し、コード領域への書き込み前後を `mprotect` で挟み、デタッチ状態の監視スレッドを起動します |
| `0x02` | UDP ポート 123 で NTP 時刻クエリを送信し、応答時刻をしきい値と照合します |
| `0x69` | プローブ用の子プロセスを `fork` し、終了ステータスを確認します |
| `0x60` | システムライブラリディレクトリ、`/proc` の環境変数、およびランタイムパスを走査します |
| `0x40` | `base.apk` および Split APK の署名を検証します（v3.1 -> v3 -> v2 -> v1/JAR） |
| `0x20` | 対象ファイルパス、ELF ヘッダー、`/proc/self/maps`、および `libc` マッピングを検証します |
| `0x33` | `dex2oat` のオプションリストを構築し、条件に合わない oat / art アーティファクトを削除します |
| `0x72` | Unix ドメインソケットを開いて接続を受け付けます（`bind` / `listen` / `accept`） |
| `0xB0` | 内部のセンチネルテーブルを変換します |

<details>
<summary>その他に確認されたモジュール ID（未分類）</summary>

`0x8E`、`0x6A`、`0x68`、`0x54`、`0x71`、`0x53`、`0xA4`、`0x58`、`0x73`、`0xA0`、`0xB2`。

これらの ID を持つモジュールは上記のモジュールとともに多段 Stage 2 ストリーム内に現れ、256 スロットのテーブルへ登録されたあと、`flags & 0x100` が立っていなければ `init` / `entry` コールバックが呼び出されます。ELF の静的復元はこれらに依存しません。
</details>
