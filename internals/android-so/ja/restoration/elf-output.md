# ELF 出力

`PT_LOAD` セグメントと動的リンクテーブルの再構築が完了すると、最終工程でプロテクター専用の構造を除去し、ファイル末尾の非ロード対象領域を書き直します。

1. **`SHT_LOUSER` の除去:** 末尾の専用セクションヘッダーを削除し、Stage 1 / Stage 2 ペイロードのバイト列は出力ファイルに含めません。
2. **`e_entry` の `0` クリア:** Android の共有ライブラリは `e_entry` ではなく `.init_array` 経由でネイティブコンストラクターを実行するため、`e_entry` をゼロクリアします。
3. **非 `SHF_ALLOC` セクションの再配置:** 保持する非ロード対象セクション（`.shstrtab` など）をすべてのロード可能セグメント（追加した `PF_R` の `PT_LOAD` を含む）の直後に詰めて配置します。`.shstrtab` を検証したうえで、更新後のセクションヘッダーテーブル（`Elf64_Shdr`）をファイル末尾に書き込み、`e_shoff` と `e_shnum` を更新します。
4. **アトミックな書き込みと再パース:** ディスクへの出力時は一時ファイルへ書き出してからアトミックにリネームし、書き込まれたバイト列を再度パースして検証します。

{% hint style="info" %}
**書き込み後の必須チェックと構造診断の区別:** 出力検証は 2 段階に分かれています。
* **必須エラー（復元を中断）:** リトルエンディアン AArch64 `ELF64` としてのパース失敗、出力ファイル長を超える `PT_LOAD` ファイル範囲、不正な `.shstrtab`、`SHT_LOUSER` セクションの残存、非ゼロの `e_entry`、または再構築したテーブルと一致しない `.dynsym` / `.rela.dyn` / `.rela.plt` のエントリ数。
* **テーブル間の整合性診断（警告として報告）:** `PT_LOAD` のアラインメント・合同条件・重複に関するリンカー相当の検査、`DT_*` タグとセクションヘッダーの一致、`DT_RELACOUNT` 先頭領域の順序、シンボルハッシュバケットの境界、再配置対象アドレスおよびシンボルインデックスの境界、`.init_array` / `.fini_array` の関数ポインター範囲。
{% endhint %}
