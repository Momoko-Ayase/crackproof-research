# モジュールストリーム

Stage 2 ストリームの抽出はルートストリーム `0xE2`（実行時の 256 スロットテーブルにはルート自身が `0xE2`、`SHT_LOUSER` のファイル末尾マッピングが `0xD0` として登録されます）から始まり、すべてのコンテナーおよび入れ子構造のインタープリターストリーム（`0xF3`..`0xF8` が指す `0xE3`..`0xE8`）を再帰的にデコードします。

## 静的復元モジュール

保護された共有ライブラリには、復元用ペイロードと並んで実行時の環境チェック用・整合性検証用モジュールが含まれています。静的な再構築では、3 つの必須モジュールと最大 3 つの任意モジュールを使用します。

| モジュール | 要件 | 静的復元における役割 |
| --- | --- | --- |
| `0x9B` | 必須 | `header_seed`、`container_seed`、バイト反転済みの AES-256 ラウンド鍵スケジュール、および `skip_aes` を保持 |
| `0x9D` | 必須 | `ProtectedDescriptor`、主 `PT_LOAD` writer コンテナー、および再配置・シンボル用の補助 ELF コンテナーを保持 |
| `0x9E` | 必須 | ディスク上の ELF から除去された非公開の `.dynsym` エントリと `.dynstr` シンボル名を保持 |
| `0x96` | 任意 | `0x9D` の補助再配置テーブルにおけるエントリごとのシンボルインデックス回転を元に戻す `auxiliary_symbol_seed` を保持 |
| `0x98` | 任意 | ステップ上限付きの AArch64 制御フロー・整数インタープリターでエミュレートすることで、本来の `.init_array` コンストラクターを復元し `RET` のみのプレースホルダーを除去 |
| `0x0C` | 任意（IL2CPP `v24.1`） | 外部の `v24.1` `global-metadata.dat` に対する `methodIndex` 置換シードと 256 エントリの例外テーブルを保持 |

## 重複レコードおよび復元対象外レコード

* **実行時専用モジュール:** 環境プローブ、インポート補助、または未分類の識別子（`0x8F`、`0x97`、`0x81`、`0x40`、`0x8E` をはじめ、[ランタイムモジュール](../runtime/modules.md)に記載された各 ID）のレコードは、ストリーム走査中にデコードおよび構造検証を行った後、ELF の再構築段階では無視します。
* **冪等な重複レコード:** 2 つのレコードが同じ `command_id` を持ち、かつ SHA-256 ダイジェストも一致する場合は 1 つだけ保持します。ダイジェストが異なる場合は、どちらのペイロードを採用すべきか推測せず抽出失敗とします。
* **必須モジュールの欠落:** ストリーム走査の完了時点で `0x9B`、`0x9D`、`0x9E` のいずれかが欠けている場合、出力ファイルを書き出さずに ELF 復元を中断します。
