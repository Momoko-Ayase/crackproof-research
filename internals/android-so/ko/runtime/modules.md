# 런타임 모듈

Stage 2 레코드는 1바이트 `command_id`(`0x00`..`0xFF`)로 각 모듈을 등록합니다. 정적 복원에서는 [모듈 스트림](../restoration/module-streams.md)에 설명된 모듈만 사용하며, 나머지 모듈은 로드 시점의 환경 검사나 보조 기능을 담당합니다.

## 스트림 인터프리터 및 부트스트랩 슬롯

| ID | 역할 |
| --- | --- |
| `0xE2`..`0xE8` | 중첩 레코드 스트림 인터프리터(`0xE2`는 복호화된 Stage 2 루트 이미지) |
| `0xF3`..`0xF8` | `0xE3`..`0xE8`에 입력으로 전달되는 직접 스트림 슬라이스(`sid = command_id - 0x10`) |
| `0xD0` | Stage 2가 `(X6, X7)` 값으로 등록하는 `SHT_LOUSER` 파일 후미 매핑 |

## 이미지, 심볼, 생성자 및 메타데이터 복원

| ID | 역할 |
| --- | --- |
| `0x9B` | `Module9bConfig`(`header_seed`, `container_seed`, 역순 AES-256 라운드 키, `skip_aes`)를 보유하는 복원 총괄 모듈로, 대상 세그먼트와 메모리 권한을 복원 |
| `0x9D` | `0x5C` 크기의 `ProtectedDescriptor`, 주 `PT_LOAD` 컨테이너, 보조 재배치·심볼 컨테이너를 담는 직접 페이로드 |
| `0x9E` | 노출된 ELF에서 제거된 숨겨진 동적 심볼 테이블(`.dynsym`) 엔트리와 `.dynstr` 문자열 |
| `0x96` | 보조 재배치 심볼 인덱스의 순열을 되돌릴 때 쓰이는 `auxiliary_symbol_seed`를 담고 있는 16바이트 블록 복호화 모듈 |
| `0x98` | 최종 생성자 디스패처로, 이미지 복원 후 대상 공유 라이브러리의 `.init_array` 콜백을 해석하고 호출(Windows 상태 코드 `280`에 대응) |
| `0x0C` | IL2CPP 빌드 전용 모듈로, `mmap`을 후킹하여 로드 시점에 `global-metadata.dat`의 난독화를 해제하며 `v24.1`용 `methodIndex` 시드와 256엔트리 예외 테이블을 내장 |
| `0xB9` | 메타데이터 관련 보조 블롭(IL2CPP 빌드에서는 데이터가 채워져 있으며, 일반 네이티브 공유 라이브러리에서는 생략되거나 비어 있음) |

## 환경 검사, 심볼 조회 및 무결성 보조 모듈

| ID | 역할 |
| --- | --- |
| `0x81` | 라이브러리 및 심볼 이름을 복호화하고 `dlopen` / `dlsym`으로 포인터를 해석해 캐싱 |
| `0x8F` | `/proc/self/cmdline` 읽기, `uid`/`gid`/`tid` 조회, 환경 토큰 관리 및 경로 소유권·권한 모드 확인 |
| `0x97` | `/proc`을 스캔하여 동일 UID 프로세스를 탐색하고, 코드 쓰기 전후로 `mprotect`를 호출하며 분리된(detached) 감시 스레드를 기동 |
| `0x02` | UDP 123번 포트로 NTP 시간 질의를 전송하고 응답을 임계값과 비교 |
| `0x69` | 검사용 자식 프로세스를 `fork`하고 종료 상태를 확인 |
| `0x60` | 시스템 라이브러리 디렉터리, `/proc` 환경 변수 및 런타임 경로 스캔 |
| `0x40` | `base.apk` 및 분할 APK 서명 검증(v3.1 -> v3 -> v2 -> v1/JAR 순서) |
| `0x20` | 대상 파일 경로, ELF 헤더, `/proc/self/maps` 및 `libc` 매핑 검증 |
| `0x33` | `dex2oat` 옵션 목록을 구성하고 일치하지 않는 oat/art 아티팩트를 제거 |
| `0x72` | 유닉스 도메인 소켓을 열어 연결 수락(`bind` / `listen` / `accept`) |
| `0xB0` | 내부 센티널 테이블 변환 |

<details>
<summary>추가로 확인된 미분류 모듈 ID</summary>

`0x8E`, `0x6A`, `0x68`, `0x54`, `0x71`, `0x53`, `0xA4`, `0x58`, `0x73`, `0xA0`, `0xB2`.

이 식별자들은 위 모듈과 함께 중첩 Stage 2 스트림에 포함되어 256슬롯 테이블에 등록되며, `flags & 0x100`이 설정되어 있지 않으면 `init`/`entry` 콜백을 실행합니다. 정적 ELF 복원에는 사용되지 않습니다.
</details>
