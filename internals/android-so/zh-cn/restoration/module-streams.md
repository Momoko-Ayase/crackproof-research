# 模块流

第二阶段流提取从根流 `0xE2` 开始（运行时该阶段在 256 槽模块表中将自身登记为 `0xE2`，并将 `SHT_LOUSER` 文件尾部映射登记为 `0xD0`），随后递归解码所有容器与嵌套解释器流（由 `0xF3`..`0xF8` 驱动的 `0xE3`..`0xE8`）。

## 静态恢复模块

每个受保护共享库除了恢复载荷外，还混有运行时环境探测与完整性校验模块。静态重建依赖三个必需模块，并按需使用最多三个可选模块：

| 模块 | 要求 | 静态恢复中的作用 |
| --- | --- | --- |
| `0x9B` | 必需 | 提供 `header_seed`、`container_seed`、字节逆序的 AES-256 解密轮密钥表与 `skip_aes` |
| `0x9D` | 必需 | 提供 `ProtectedDescriptor`、主 `PT_LOAD` 写入容器与辅助 ELF 容器 |
| `0x9E` | 必需 | 提供从磁盘 ELF 中剥离的隐藏 `.dynsym` 符号项与 `.dynstr` 符号名称 |
| `0x96` | 可选 | 提供 `auxiliary_symbol_seed`，用于还原 `0x9D` 辅助重定位表中按行轮换的符号下标 |
| `0x98` | 可选 | 包含构造函数恢复代码；静态恢复时通过受限的 AArch64 控制流与整数指令模拟执行该模块，还原 `.init_array` 真实构造函数并剔除单条 `RET` 占位桩 |
| `0x0C` | 可选（IL2CPP `v24.1`） | 为外部 `v24.1` 版 `global-metadata.dat` 提供 `methodIndex` 置换种子与 256 项例外表 |

## 重复记录与非恢复记录处理

* **仅运行时模块**：环境探测、导入辅助或尚未归类的模块标识（如 `0x8F`、`0x97`、`0x81`、`0x40`、`0x8E` 及[运行时模块](../runtime/modules.md)列出的其他项）在遍历记录流时仍会正常解码并校验边界，但在重建 ELF 时直接忽略。
* **幂等重复记录**：若两条记录带有相同 `command_id` 且 SHA-256 摘要完全一致，提取流程仅保留一份副本；若摘要不一致，则直接报错中止。
* **缺少基础模块**：流遍历结束后，只要 `0x9B`、`0x9D` 或 `0x9E` 中缺少任意一个，ELF 恢复即报错中止，不生成残缺输出。
